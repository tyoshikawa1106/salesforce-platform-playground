# 画面内の共通エラー表示

## 概要

画面LWCとモーダルの操作・取得処理で捕捉した例外を、処理場所と種類付きで表示する共通部品です。画面を持たないPDFアクションは同じ診断をエラートーストへ表示します。

## 目的・利用場面

画面の業務メッセージを維持しながら、どのLWCのどの処理が失敗したかを利用者が確認できるようにします。成功ログやAPI応答本文を診断情報へ記録しません。

## 対象実装・メタデータ

| 種別          | 完全名                                   | 役割                                                                                 |
| ------------- | ---------------------------------------- | ------------------------------------------------------------------------------------ |
| APIモジュール | `uiErrorBoundary` / `uiErrorBoundary.js` | `withUiErrorBoundary`で例外境界と診断状態を画面・モーダルへ追加                      |
| 内部表示LWC   | `uiErrorPanel` / `uiErrorPanel.js`       | 処理場所・種類・取得できたJS位置の表示と閉じる通知                                   |
| APIモジュール | `errorUtils` / `errorUtils.js`           | `createClientErrorDetails`で本文を含まない診断を生成。既存の業務メッセージ変換も維持 |

## 入力

捕捉した例外、利用元が固定値で指定するコンポーネント名・処理名・処理段階を受け取ります。表示部品には生成済みの診断だけを渡します。

## 処理内容

1. 利用元は操作・wire・ライフサイクルの入口で自画面の例外を捕捉します。既存の通信失敗処理には診断を追加します。
2. 例外名は通常のError名だけを採用します。Salesforce応答は`SalesforceError`とし、任意の例外名を表示へ持ち込みません。
3. スタックからURL・端末パスを除き、JSファイル名と行・列だけを重複除去して最大8件保持します。
4. 利用元は`clientError`を表示へ反映し、診断だけを`console.error`へ出力します。同じ位置・種類・スタックの再通知は抑制します。
5. 親の`errorCallback`は、その子の描画と宣言的イベントの例外を受け止めます。非同期のURL生成や描画後処理は、そのPromiseで明示的に捕捉します。
6. 診断を閉じる操作は診断だけを解除し、入力値・業務エラー・実行状態は変更しません。

## 出力・更新対象

画面内の`role="alert"`へ処理場所・例外種別・最初のJS位置を表示します。診断がなければ警告・操作部品を表示しません。Salesforceレコードの更新・削除や自動再試行は行いません。

## 権限・実行条件

新しい権限・プロファイル依存・カスタム権限は追加しません。利用元の既存の権限・操作ロック・応答世代判定を維持します。`NavigationMixin`と`LightningModal`は基底クラスのまま拡張します。

## エラー処理

診断のコンソール出力に元のError、メッセージ、入力値、API応答本文、認証情報は渡しません。既存の業務メッセージと再試行手順は利用元で管理します。終了済み・古い世代の通信失敗は、利用元で破棄してから診断を生成します。

## テスト・確認観点

- `uiErrorBoundary.test.js`：正常時の無出力、診断の秘密情報除外、子の例外通知、重複抑止、診断を閉じた後の再通知、位置情報の上限。
- `uiErrorPanel.test.js`：正常時の非表示、診断の表示、閉じる通知とアクセシビリティ。
- 各画面・モーダルのJest：取得・操作失敗を実際のwire／イベントで起こし、処理場所の表示と元の画面の維持を確認。
- PDFアクション：失敗時のトーストに処理場所が含まれることと二重起動防止を確認。

## 制約・注意事項

`errorCallback`は自身の描画例外や任意の非同期例外を自動では捕捉しません。自身の操作と非同期処理は利用元の明示的な捕捉で扱います。Salesforce全体やブラウザ拡張など、当該コンポーネント外のエラーを抑止するグローバルハンドラーは登録しません。

外側背景は組織の配置先を透過表示します。既に背景指定のない画面・カードだけを持つ画面は追加変更しません。図のキャンバス、カード、固定ヘッダー、モーダル本文、候補一覧、編集中・警告の背景はそれぞれ維持します。

## 既知の差異・確認事項

比較対象なし：共通部品の外部契約はありません。捕捉範囲は本書に記載したLWCの境界に限定されます。
