# ユーザー作成アシスタント

## 概要

Salesforce アプリの「OAuth トークン発行」の次に配置する、新規ユーザーの作成画面です。コピー元の情報を見ながら入力し、そのユーザーに割り当てられた権限セットや権限セットグループを引き継げます。

## 目的・利用場面

同じユーザーライセンス・ロール・プロファイルで新しい利用者を登録するときに使用します。既存ユーザーを置き換える場合は、元ユーザーの編集と無効化も同時に行えます。

## 入力

- 地理位置情報は緯度と経度を個別の数値で表示・入力します。複数選択リストは選択済みの値を表示し、編集時は各パネルの横幅を使い、「選択可能」と「選択済み」の間で候補を移動します。
- 連動選択リストの候補は左右それぞれの制御項目に従います。コピー先に引き継げない選択値は「選択対象外」と表示し、選び直すか解除してから確認画面に進みます。確認中に候補が更新され、選択値が対象外になった場合もフォームに戻ります。
- 権限確認・取得・入力・保存のエラーは、画面見出し直下の共通の通知枠に表示します。
- リッチテキストは書式付きで表示・編集し、元の本文に含まれる画像もコピーします。保存前のファイルアップロードを防ぐため、ツールバーの画像・リンク挿入ボタンを非表示にします。
- 氏名・ユーザー名からコピー元を選びます。新規側の編集可能項目には、選択時点の元ユーザーの値を設定します。空欄にできる項目は、コピー元が空欄なら新規側にも空欄を引き継ぎます。ユーザー名やニックネームなど、一意性が必要な値は保存前に調整します。ユーザーライセンス・ロール・プロファイルは両側とも参照専用です。
- コピー元の無効化は初期状態でオフです。ログイン中の本人を選ぶと、無効化はオフのまま操作できず、本人をコピー元として新規ユーザーを作成できます。他のユーザーを選んで無効化をオンにすると元側の編集可能項目を変更できます。オフに戻すと元側の編集を取り消し、新規側の入力は保持します。
- 検索・読み込み・保存の対象は、取引先責任者に紐づかない標準ユーザーと社内の Chatter Free ユーザーです。External Identity と Chatter External のユーザーはコピー元にできません。取引先責任者 ID はフォームに表示しません。
- 代理承認者はユーザーまたはグループのレコード ID を指定できます。SAML 統合 ID はテキスト入力です。
- 「有効」を含むチェックボックス型の項目は、両側ともチェックボックスで表示します。新規側の「有効」はチェック済みの参照専用項目です。コピー元の状態にかかわらず、有効なユーザーを作成します。
- 暗号化項目は両側とも対象外です。Apex はコピー元の取得と保存に使用する項目一覧から除外し、保存要求で指定された場合も拒否します。
- 権限セットと権限セットグループの引き継ぎは、ともに初期状態でオンです。個別に解除できます。
- 「パスワードリセットメールを送信」はコピー元を選ぶたびにオンになります。確認画面の「新規ユーザー」欄に「送信する」または「送信しない」と表示します。オンの場合は、作成・権限割り当ての成功後に新規ユーザーへのリセット通知を要求します。

## 処理内容

1. コピー元を選択すると、現在の組織の User 項目定義と実行者の項目権限から表示項目を生成します。標準項目はユーザー編集画面に対応するグループに配置し、カスタム項目は日本語の表示ラベル順で表示します。
2. コピー元と新規側を別々のボックスに並べ、各ボックス内の項目を2列に揃えます。住所は郵便番号、都道府県、市区郡、町名・番地、国の順です。スマートフォンの幅では項目を1列にします。狭い画面ではコピー元、新規側の順に縦に表示します。
3. 保存時に元ユーザーのプロファイルとロールを再取得します。無効化を選んだ場合は元側の変更を保存してから新規ユーザーを作成します。
4. 有効な直接割り当てとグループ割り当てのうち選んだ種類を、元の有効期限で付与します。グループはグループ単位で付与し、新規側にすでにある割り当てを重複登録しません。

## 出力・更新対象

User を作成し、成功したユーザーへのリンクを表示します。無効化を選んだ場合は元ユーザーの指定項目と有効状態を更新します。引き継ぎの対象は PermissionSetAssignment です。

## 権限・実行条件

[SalesforceApplicationUser](../../../../force-app/main/default/permissionsets/SalesforceApplicationUser.permissionset-meta.xml) がタブ表示を、[LwcUserCreateAssistant](../../../../force-app/main/default/permissionsets/LwcUserCreateAssistant.permissionset-meta.xml) がタブ表示と Apex の入口へのアクセスを付与します。画面を開くとき、コピー元を読み込むとき、保存するときに、Apex は実行者の実効権限を取得し、「設定・定義を参照」→「ユーザーの管理」→ User オブジェクトの参照 → 作成 → 編集の順に確認します。権限が不足するとフォームを閉じ、最初に不足した権限名を表示します。実効権限の取得に失敗した場合や結果が 0 件の場合は「実行ユーザーのシステム権限を取得できませんでした。」と表示します。権限セットとグループの割り当てには、実行者が組織ですでに持つ割り当て権限を使用します。サーバーでも固定項目と書き込み可能な項目を検証します。

## エラー処理

- 作成前の確認画面は「コピー元ユーザー」「新規ユーザー」「権限の引き継ぎ」の順に表示します。両側に氏名・メール・ユーザー名を示し、作成後の状態は「有効」の読み取り専用チェックボックスで示します。新規側にはリセットメールの送信有無を表示します。キャンセルすると入力に戻ります。
- 確認画面で作成を確定したときに左右のユーザー名を比較し、同じ場合は新規側のユーザー名欄に理由を表示します。エラーの概要はページ見出しの直下に表示し、通知へフォーカスを移します。
- コピー元では変更した項目だけを画面で検証して送信します。新規ユーザー側はすべての編集欄を検証します。
- 元ユーザーの更新、新規作成、権限割り当ては同じトランザクションで行います。どれかが失敗すると、元ユーザーの無効化を含めて取り消します。
- 確認画面の確定から保存要求を1回送ります。確認画面は項目ごとに行を分けて表示し、確定すると入力エラー、保存中、または保存結果を表示します。保存結果にユーザー ID がない場合、通信が切れた場合、30秒以内に応答がない場合は、再実行前に設定のユーザー一覧で作成結果を確認するよう案内します。応答を待っている間は再送を防ぎ、その後に確定結果が届けば画面に反映します。保存失敗時は入力とチェック状態を保持します。権限割り当てでライセンスが不足した場合は、該当する引き継ぎをオフにして再試行できます。ユーザーライセンス自体の枠不足はユーザー作成時に通知します。
- コピー元の切り替え中は前の取得結果を無視します。保存中はフォームをロックし、二重送信を防ぎます。保存中に連動候補の取得が失敗しても、作成に成功した場合は成功結果だけを表示します。保存も失敗した場合はフォームを閉じ、保存と候補取得の両方のエラーを同じ通知に表示します。

## 関連コンポーネント

対象ユーザーの検索に標準レコードピッカーを使用します。フォームでは入力型と選択肢を User の項目定義から決定し、参照先のオブジェクト情報をピッカーで取得できない場合はレコード ID を入力します。

## テスト・確認観点

- Jest は初期値、項目順、左右の編集可否、無効化解除、取得の競合、保存失敗時の再試行、送信中の再接続を確認します。
- Apex テストは作成、元ユーザーの保持・無効化、固定項目、割り当ての種類・期限、失敗時の取り消しを確認します。
- Scratch Org の実画面では、別のユーザーをコピー元にして4つの作成オプションを切り替え、確認画面の選択値が Apex の保存要求に届くことを確認します。本人に切り替えたときは、無効化がオフに戻り、コピー元の項目が参照専用になることを確認します。

## 制約・注意事項

- 元ユーザーのユーザー名を新規側で再利用する場合、元のユーザー名を変更し、組織の一意制約を満たす必要があります。組織の入力規則で変更が禁止されている場合は、新規側に別のユーザー名を入力します。
- 表示名の五十音順には日本語ロケールの照合順を使用します。漢字の表示ラベルに対する読み仮名の推定は行いません。
- 利用可能な項目・選択肢・ライセンス・ロールの条件は組織と実行ユーザーによって異なります。

## 既知の差異・確認事項

標準項目のグループと表示順は設定画面を参考にした画面定義です。Salesforce の設定画面に対する組織別のレイアウト変更をそのまま再現する構成ではありません。
