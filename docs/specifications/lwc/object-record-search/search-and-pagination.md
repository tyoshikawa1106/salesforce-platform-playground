# 検索・ソート・ページング

## 概要

`objectRecordSearch` におけるレコード一覧の検索、ソート、カーソルページングの詳細仕様です。

## 入力

- `metricKey`: `ObjectMetricCatalog` に定義されたカードキー
- `searchTerm`: `Name` 相当項目へ適用する検索語
- `sortBy`: 一覧で選択されたソート項目
- `sortDirection`: `asc` または `desc`
- `pageToken`: 次ページの開始位置を表すトークン
- `pageNumber`: 画面に表示するページ番号

## 処理内容

1. カードキーから許可済みの対象オブジェクトを解決します。
2. Describe 結果から `Name` 相当項目と、参照可能な追加表示項目を決定します。
3. Service が検索語の前後空白を除去し、検索語があり、`Name` 相当項目が filterable な場合は部分一致条件を追加します。検索語は任意フィルターとして扱い、空の場合も初期一覧を取得します。
4. ソート項目を `Name` 相当項目または参照可能な追加表示項目に限定します。
5. Selector が許可済み識別子から動的 SOQL を組み立て、検索条件とページ境界値を bind 値として設定します。
6. Selector が `AccessLevel.USER_MODE` で検索し、次ページ判定用の1件を含む最大51件を取得します。
7. 51件目の有無で次ページを判定し、最後の表示行に対応する元レコードから次ページトークンを作成します。

ソートは指定項目を第1キー、Idの昇順を第2キーとします。null値は第1キーの末尾に配置します。

検索、ソート、ページ移動で問い合わせ条件が変わった時点から成功または失敗の応答を受け取るまで、追加の検索、ソート、前後ページ操作を抑止します。同一条件の再操作では新しい応答待ちを開始しません。

## 出力・更新対象

- 検索画面設定
- 最大50件の表示行
- ページサイズと現在ページ番号
- 次ページの有無と次ページトークン

追加表示項目の`fieldValues`はBoolean、数値、日付、日時、nullを元の型で返します。JSON上では日付は日付文字列、日時はUTCのISO 8601形式となり、日時のミリ秒も保持します。Name相当項目がnullの場合のId代替ラベルは表示専用です。ページトークンには代替ラベルや空文字への変換を適用せず、元のソート値を保持します。

次ページがない場合は `hasNextPage` を `false`、`nextPageToken` を空文字列で返します。

レコードの作成、更新、削除は行いません。

## 権限・実行条件

- 対象オブジェクトが参照可能かつクエリ可能で、`Name` 相当項目を参照できる必要があります。
- 表示項目は項目レベル参照権限で絞り込みます。
- 一覧取得は `with sharing`、`AccessLevel.USER_MODE` で利用者の共有設定と権限を適用します。
- 検索語なしの初期一覧は、許可済みオブジェクトと項目、決定的なソート、51件の取得上限を適用します。

## エラー処理

- 未定義のカードキー、参照不可またはクエリ不可のオブジェクト、参照不可の `Name` 相当項目は利用者向けエラーにします。
- 許可されていないソート項目、壊れたページトークン、対象オブジェクト、ソート項目、方向のいずれかが現在の条件と一致しないトークンは検索エラーにします。
- 予期しない例外は検索用の一般化メッセージへ変換します。

## テスト・確認観点

- `ObjectRecordSearchControllerTest`、`ObjectRecordSearchServiceTest` で、検索語の正規化、任意フィルターなしの初期一覧、50件／51件のページ境界を確認すること
- `ObjectRecordSearchSelectorTest`、`ObjectRecordSearchQueryPlanTest`、`ObjectRecordSearchSortSupportTest` で、動的 SOQL と bind、固定取得件数、昇順・降順ソート、null値、カーソル、不正ページトークンを確認すること
- `objectRecordSearchPaging.test.js`、`objectRecordSearchState.test.js` で、検索実行、server-side sort、前後ページ移動と状態更新を確認すること
- 検索語の前後空白を除去し、`Name` 相当項目へ部分一致を適用すること
- 検索語が空の場合は検索条件なしで取得すること
- 表示項目と項目レベル参照権限が一覧列へ反映されること
- 昇順、降順、null値、同値レコードで順序が安定すること
- Booleanのfalse、数値の0、日付とUTC日時、nullを元レコードから表示・トークン復元まで保持すること
- nullが51件続く結果を重複なく読み切り、NameのId代替ラベルをページ境界に混ぜないこと
- 50件と51件の境界で次ページ有無を正しく判定すること
- 前ページへ戻った場合に保持したページトークンを使用すること
- 応答前に「次へ」を連続操作してもページ番号とトークンを一度だけ更新し、応答後に次の操作が可能になること
- 同一検索条件または同一ソート条件の再操作では取得済みの次ページ情報を保持し、待機状態に残らず、検索失敗後に条件を変更して再検索できること
- ソート方向が欠けたトークンと、ソート項目または方向が現在の条件と一致しないトークンを拒否すること

## 制約・注意事項

- 1ページの表示件数は50件固定です。
- 検索対象は `Name` 相当項目だけです。
- ソート対象は `Name` 相当項目と、権限確認済みの追加表示項目に限定されます。
- ページ番号は表示用であり、レコード取得位置はページトークンで管理します。
- 日時境界はISO 8601形式で復元します。タイムゾーン情報を持たない旧日時トークンは無効となるため、更新前から開いている検索画面は再検索が必要です。
- ページトークンは対象オブジェクト、ソート項目、方向、最終行のソート値とIdをJSONとしてシリアライズした内部カーソルです。署名や暗号化は行わず、Apexで構造、現在の検索条件、IdのSObject型との一致を検証します。

### 大量データとページング

- 1回の検索では51件を取得し、表示する50件と次ページ有無を判定します。
- OFFSETは使用せず、ソート値とIdを保持するカーソルページングで取得位置を管理します。
- 検索条件またはソート条件を変更した場合はページ状態を先頭へ戻し、以前の条件で生成したページトークンを再利用しません。

## 既知の差異・確認事項

- 現行実装は検索関連Apexクラスと `objectRecordSearch` のページング関連JavaScript、代表テストから確認しています。
