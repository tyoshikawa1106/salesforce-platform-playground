# 外部クライアントアプリ認証管理

## 機能の用途

管理者がローカル外部クライアントアプリのコンシューマ鍵と秘密を更新する画面です。［適用］で新しい鍵と秘密を生成して有効にします。管理者はSalesforce標準設定画面で新しい値を確認して連携先に登録し、切り替えを確認してから、この画面で旧資格情報を削除します。

### 利用条件

- 利用者には、カスタム権限「外部クライアントアプリ認証管理」 と、Apexクラス `ExternalClientAppManagerController` を実行する権限が必要です。
- 権限セット「LWC：外部クライアントアプリ認証管理」は管理用APIに接続するユーザーに `External Client App Developer` と `View Client Secret` に加え、これらの前提となる `ExternalClientAppAdmin` と `ExternalClientAppViewer` を付与します。
- 外部クライアントアプリケーション設定の「REST APIを使用した外部クライアントアプリケーションのコンシューマーの秘密へのアクセスを許可」を管理者が事前に有効にします。
- 検索・更新の対象は、管理用接続に使用するアプリを除くローカルアプリです。

### 管理用接続

| メタデータの種別       | 定義上の表示ラベル             | API名                      | 用途                                                                                                          |
| ---------------------- | ------------------------------ | -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 外部クライアントアプリ | 外部クライアントアプリ認証管理 | `ExternalClientAppManager` | 管理用接続のOAuth認証に使用する。                                                                             |
| 外部認証IDプロバイダー | 外部クライアントアプリ認証管理 | `ExternalClientAppManager` | 管理用アプリのコンシューマ鍵と秘密を使用して認証する。                                                        |
| 外部ログイン情報       | 外部クライアントアプリ認証管理 | `ExternalClientAppManager` | ブラウザーを使ったOAuth認証を定義し、利用者ごとのプリンシパル（`ExternalClientAppUserPrincipal`）を使用する。 |
| 指定ログイン情報       | 外部クライアントアプリ認証管理 | `ExternalClientAppManager` | 導入先組織の［私のドメイン］を接続先とし、認証ヘッダーにアクセストークンを設定する。                          |

管理用アプリには `api`、`refresh_token`、`openid` の各スコープと、外部認証IDプロバイダーのコールバックURLを登録します。鍵と秘密は外部認証IDプロバイダーに設定します。

権限セット「LWC：外部クライアントアプリ認証管理」は、外部ログイン情報のプリンシパルを使用する権限を付与します。スクラッチ組織では、この権限セットと接続定義を同じ段階でデプロイします。利用者が画面から認証すると、Apexはユーザー情報APIが返す組織IDとユーザーIDを、現在の組織と実行ユーザーのIDと照合します。

## アクセスするデータ・項目

| 対象                   | 使用する項目                                                                                             | 用途                                                                                                                              |
| ---------------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 外部クライアントアプリ | アプリID（`Id`）、API名（`DeveloperName`）、表示ラベル（`MasterLabel`）、配布状態（`DistributionState`） | Tooling APIで候補を検索し、選択後は対象IDとAPI名を照合する。                                                                      |
| OAuthコンシューマー    | `consumers[].id`、`name`                                                                                 | REST APIで対象アプリのコンシューマーを取得し、コンシューマーが1件であることを確認し、そのIDをステージ資格情報の取得先パスに使う。 |
| ステージ資格情報       | `stagedCredentials[].id`、`state`、`expirationDate`                                                      | 一覧表示、生成、適用、削除と各操作の完了確認に使う。鍵と秘密の値は画面に返さず、独自のDB・ログ・キャッシュにも保存しない。        |
| 管理用接続             | ユーザー情報APIの `organization_id`、`user_id`                                                           | Apex実行者の組織・ユーザーと照合する。認証解除は本人の接続に使う資格情報に限る。                                                  |
| オブジェクト定義       | `ExternalClientApplication` の `themeInfo.iconUrl`                                                       | 選択欄のアイコンをUI APIから取得する。取得できない場合は代替アイコンを表示する。                                                  |

検索語が空の場合のSOQLは次のとおりです。

```sql
SELECT Id, DeveloperName, MasterLabel, DistributionState
FROM ExternalClientApplication
WHERE DistributionState = 'Local'
  AND DeveloperName != 'ExternalClientAppManager'
ORDER BY DeveloperName
LIMIT 200
```

検索時はラベルまたはAPI名の部分一致条件を加えます。入力した `%` と `_` は文字として扱います。選択後の照合では検索語の代わりにIDの一致条件を加えるため、最初の200件に含まれないアプリも操作できます。

## 操作

1. タブを開き、認証を求められたら［認証］から管理用APIへのアクセスを許可し、ページを再読み込みします。
2. ラベルまたはAPI名を入力してアプリを選択します。上下の矢印キーで候補を移動し、Enterキーで選択します。Escキーで候補を閉じます。×またはDeleteキーで選択を解除できます。
3. ［適用］を押し、確認画面に対象アプリの15桁または18桁のIDを入力します。適用が完了すると成功通知が表示されます。
4. 連携先を切り替えた後、「ステージ資格情報」の一覧で「適用済み」の行を確認します。その行の［削除］を押し、確認ダイアログで削除を承認します。ステージに資格情報がない場合、この一覧は表示されません。
5. 本人の管理用接続を解除するときは［認証解除］を押して承認します。アプリの選択が解除され、認証を案内する画面に戻ります。

## エラー判定

| 条件                                                             | 処理の状態と利用者の対応                                                                                                                                     |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 利用者に必要なカスタム権限がない                                 | 候補を取得せず、必要な権限セットを案内する。                                                                                                                 |
| 本人確認ができない                                               | 資格情報の操作を開始しない。認証開始URLを取得できた場合は再認証できる。本人確認またはURL取得の応答待ちが30秒に達したら、処理名と再読み込みの案内を表示する。 |
| 確認用IDが一致しない                                             | 更新要求を送らず、モーダルの入力欄にエラーを表示する。その場で修正できる。                                                                                   |
| 参照APIがHTTP 403を返す                                          | REST APIによる秘密へのアクセスを許可する設定と、利用者の権限を確認するよう案内する。HTTPステータスだけではどちらが原因か判定できない。                       |
| 変更直前の確認で対象や状態が一致しない                           | Apexはその変更要求を送信せず、`notStarted` を返す。処理を開始できなかった理由を画面に表示して後続処理を止める。                                              |
| 変更要求の送信後、通信エラーや不正な応答などで結果を確認できない | 資格情報がすでに変更された可能性がある。処理を止め、対象アプリを選び直して最新状態を確認するよう案内する。自動再送・ロールバックは行わない。                 |
| 認証解除を要求した後、結果を確認できない                         | 資格情報の操作を停止し、ページを再読み込みして認証状態を確認するよう案内する。                                                                               |

## 処理詳細

### 認証と対象選択

指定ログイン情報を使ってREST APIに接続します。アクセストークンの更新はSalesforceが行います。続いて、ユーザー情報APIで接続先の組織とユーザーを確認します。本人確認に成功してから候補を取得します。検索語を変更した場合は最新の検索結果を表示します。画面に戻ったとき、アプリが未選択であれば直前の検索語で候補を取得します。選択済みであれば、アプリIDで管理対象であることを確認してからステージ資格情報を再取得します。管理対象から外れていれば選択を解除します。

### 鍵と秘密の更新

［適用］では確認モーダルを開く前に最新のステージ一覧を取得します。

| ステージの状態        | ［適用］時の判定                                                                                      | 手動削除 |
| --------------------- | ----------------------------------------------------------------------------------------------------- | -------- |
| 空                    | ID確認後に生成へ進む。                                                                                | 対象なし |
| 未適用（`active`）    | 未適用の1件だけなら、ID確認後にその行を削除し、空になったことを確認して生成する。複数件なら停止する。 | 可       |
| 適用済み（`rotated`） | 旧資格情報を保持して停止する。連携先の切り替えを確認してから手動削除する。                            | 可       |
| 期限切れ（`expired`） | 停止し、期限切れの行を削除するよう案内する。                                                          | 可       |
| 不明                  | 停止し、標準設定画面での確認を案内する。                                                              | 不可     |

ApexはアプリIDとコンシューマーIDからステージ資格情報のAPIパスを組み立て、生成直前にも一覧が空であることを確認します。POSTで新しい資格情報を生成し、返されたIDの資格情報が一覧で「未適用」になっていることを確認します。次に、そのIDを指定してPATCHで適用を要求します。同じ資格情報の状態が「適用済み」に変わったことを確認してから、画面に適用完了を通知します。適用後のステージに残るのは旧資格情報です。

REST APIの操作対象は、アプリIDとコンシューマーIDで決まります。ステージ一覧のパスは `/services/data/v68.0/apps/oauth/credentials/{アプリID}/{コンシューマーID}/staged` です。

| 操作     | HTTPメソッドと対象                                                          | 完了の判定                                                 |
| -------- | --------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 一覧取得 | ステージ一覧にGET                                                           | 応答にステージの配列がある。空の配列は取得成功として扱う。 |
| 生成     | ステージ一覧にPOST                                                          | 生成されたIDが取得後の一覧にあり、状態が未適用である。     |
| 適用     | ステージ一覧のパスに対象のステージIDを加えてPATCH（`{"command":"rotate"}`） | 同じIDの状態が適用済みである。                             |
| 削除     | ステージ一覧のパスに対象のステージIDを加えてDELETE                          | 削除後の一覧にそのIDがない。                               |

### 手動削除と再実行

手動削除ではアプリ名と状態を確認画面に表示し、承認後にApexで対象ステージのID・状態を再照合します。DELETE後の一覧から対象IDが消えたことを確認して成功を通知します。

処理中は、同じ画面から再度実行したり対象アプリを変更したりできません。別の管理者の画面では同じアプリを操作できるため、同時に更新しないようにします。画面を離れた場合は未送信の後続処理を止めます。送信済みの変更は取り消せないため、復帰時に状態を再取得します。再実行時は、ステージ資格情報の一覧をあらためて取得します。永続的な操作履歴は保存しません。

### 既知の差異・確認事項

発行済みのアクセストークン、更新トークン、既存のセッションへの影響は未確認です。この画面の成功判定はステージ資格情報の状態に基づきます。トークン失効の判断にはSalesforceの仕様と対象組織での確認が必要です。

- [REST秘密アクセス設定の推奨構成](https://help.salesforce.com/s/articleView?id=xcloud.shr_external_client_app_settings_rest_api_secret_masking.htm&language=en_US&type=5)
