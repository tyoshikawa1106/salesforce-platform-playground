# 外部クライアントアプリ認証管理

## 概要

ローカル外部クライアントアプリのコンシューマ鍵・秘密を、コマンドを使わずに更新する管理者向け画面です。「適用」ボタンから生成・適用を続けて実行します。適用後の旧コンシューマ鍵と秘密はステージに保持し、利用者が確認して手動削除します。

## 目的・利用場面

管理者が組織内のアプリを選択し、鍵・秘密の更新、残存するステージの確認・削除、工程別の実行結果確認を行います。新しい値のコピーと連携先への登録はSalesforce標準設定画面および連携先で行います。

## 対象実装・メタデータ

| 種別             | API名                                | 役割                                           |
| ---------------- | ------------------------------------ | ---------------------------------------------- |
| LWC              | `externalClientAppManager`           | 認証、対象選択、更新・削除、実行結果表示       |
| JavaScript       | `externalClientAppManager.js`        | 操作順序、確認、画面状態への反映               |
| JavaScript       | `externalClientAppManagerLogic.js`   | 選択肢、ステージ状態、公開結果の表示変換       |
| Apex             | `ExternalClientAppManagerController` | 公開入口、API呼び出し順序、例外境界            |
| Apex             | `ExternalClientAppManagerService`    | 権限・対象・ステージ状態の検証、公開属性の選別 |
| Apex             | `ExternalClientAppManagerApiClient`  | 管理用接続によるREST通信と標準認証API          |
| カスタム権限     | `ManageExternalClientAppCredentials` | 公開操作の利用制限                             |
| 権限セット       | `LwcExternalClientAppManager`        | Controller、カスタム権限、タブへのアクセス     |
| タブ             | `ExternalClientAppManager`           | 画面入口                                       |
| アプリケーション | `Salesforce`                         | ナビゲーションへの追加                         |

内部確認モーダルは `externalClientAppCredentialModal` です。`externalClientAppCredentialModal.js` が標準モーダルの入力と検証結果を扱い、`externalClientAppCredentialModalLogic.js` が正規化済み対象IDへの照合を行います。

各実装とテストはこの機能内で完結し、他機能のController、Service、共通テストデータ作成クラス、LWCを参照しません。Serviceは通信クラスを参照せず、入力・応答の検証と公開値への変換だけを担当します。例外の公開メッセージへの変換はControllerが行います。選択肢の表示配列は候補取得時に生成し、再描画ごとの変換を行いません。

## 入力

- 更新対象のローカル外部クライアントアプリ。初期選択は「-- なし --」です。
- 青い「適用」ボタンと、確認ポップアップで入力する外部クライアントアプリケーションID（15桁または18桁）。
- 操作確認ダイアログの承認。

画面から送信されたアプリID・API名・ステージID・状態はサーバーで再検証します。URLやコンシューマ鍵・秘密を入力として受け取りません。

## 処理内容

ページヘッダーはSLDSのPage Headerに統一し、左に機能アイコンとタイトル、右に既存の操作を配置します。幅が足りない場合は操作を折り返します。

### 認証と対象選択

初期表示で管理用API接続の本人性を確認します。接続確認が成功するまでは、確認中・未認証・確認不能のいずれでも「認証」を表示します。認証開始URLは接続確認の結果と独立して取得し、確認不能の場合も認証をやり直せます。URL取得中や設定不備でURLを取得できない場合はボタンを無効表示し、取得失敗時は確認先を案内します。状態確認とURL取得の内部例外は公開しません。機能権限とURLの接続先検証はサーバー側で維持します。

接続確認に成功した場合だけローカルアプリの候補を取得し、「認証解除」と更新・削除の操作領域を表示します。認証元の`ExternalClientAppManager`は候補から除外します。候補上限は200件とし、上限超過や未完了の応答は部分一覧として公開しません。

対象選択後に青い「適用」ボタンを表示します。確認用IDは専用のLightningModalの空欄へ入力します。15桁・18桁の同一IDを画面とApexの両方で照合します。対象のIdとコンシューマーIdから固定のAPIパスを構築し、`stagedCredentialsUrl`の有無には依存しません。

### 自動更新

適用ボタンを押すと最初にステージ一覧を取得し、旧コンシューマ鍵と秘密が残っていれば画面内にエラーを表示して停止します。この場合は確認モーダルを開きません。旧コンシューマ鍵と秘密がない場合だけ`専用のLightningModal`を開き、対象の名称と適用内容を表示して確認用IDの入力を求めます。IDの不一致ではモーダルを閉じず、入力欄の直下にエラーを表示します。IDの不一致では変更APIを呼び出しません。全体の処理順序は次のとおりです。キャンセル時は事前の一覧参照だけを行い、変更要求は送信しません。

1. 確認モーダルより先に最新のステージ一覧を取得し、rotated・expiredや未知の状態があれば画面内エラーで停止します。
2. 旧コンシューマ鍵と秘密がない場合は確認モーダルを開き、IDの一致後に処理を続けます。未適用のactiveステージが残っている場合は、一件であることとID・状態を再照合して自動削除し、消失を確認します。rotatedでは連携先の切り替え確認と手動削除、expiredでは期限切れ資格情報の削除を案内します。未知の状態では削除を案内せず、標準設定画面での状態確認へ案内して停止します。削除後に別の資格情報が現れた場合も状態別の案内で停止します。不明状態には削除を促しません。削除失敗・状態変更・結果不明の場合は生成へ進みません。
3. すべてのステージが空であることをApexでも確認して新しい鍵・秘密を生成し、旧コンシューマ鍵と秘密とは区別して一件のactiveステージを確認します。未知の状態では生成を停止します。
4. 今回生成した同じIDを適用し、rotated状態を確認します。ステージに残った旧コンシューマ鍵と秘密は削除しません。

認証済み画面の処理中は「コンシューマ鍵と秘密の更新」カード内の右上に、組織エクスプローラーと同じリング型のスピナーを表示し、状況の文言は読み上げ用の代替テキストに設定します。処理中は対象変更と二重実行を禁止します。途中の拒否・通信失敗・結果不明・想定外の一覧で後続を停止し、同じ実行内での自動再送やロールバックは行いません。生成と適用を確認した場合だけ成功トーストを表示します。

### 旧コンシューマ鍵と秘密の確認と手動削除

アプリ選択時にステージ一覧をAPIから取得します。再取得ボタンと空状態の案内は表示せず、取得済みの資格情報がある場合だけ独立したセクションを表示します。同じ画面へ再接続した場合は認証とアプリ候補を確認し、選択中アプリが引き続き候補にあればステージ一覧を自動再取得します。候補から外れた場合は選択を解除します。離脱前の一覧は破棄し、再取得失敗時も表示しません。アプリを選択し直した場合も最新の一覧を取得します。ブラウザ側への永続保存は行いません。

「ステージ資格情報」セクションにステージID・状態・APIが返す有効期限・赤い削除ボタンを表示します。状態欄はactiveを「未適用」、rotatedを「適用済み」、expiredを「期限切れ」、未知の値を「不明」と表示します。APIへの送信には元の状態値を使用します。生成・適用が途中で止まった未適用資格情報も手動削除できます。秘密の値自体は表示しません。

削除確認にはアプリ名と資格情報の状態を表示し、旧コンシューマ鍵と秘密の場合は連携先の切り替え確認を案内します。削除ボタンの確認を承認した場合だけ、その一件のID・状態をサーバーで再照合して削除します。キャンセルや画面切り替えでは削除しません。次回の生成時も適用済みの旧コンシューマ鍵と秘密は自動削除しません。完了応答と対象IDの消失を確認してから成功とします。結果不明時はアプリを選択し直して一覧を取得するまでセクションを表示しません。

### 再実行

結果未確認の場合は、アプリを選択し直して現在の状態を確認してから適用ボタンで再実行します。毎回最新状態を取得し、未適用ステージだけを自動削除してから生成します。適用済みの旧コンシューマ鍵と秘密があれば生成を停止し、削除は個別に確認して行います。途中工程からの再開や画面離脱後の後続API送信は行いません。画面離脱時に処理の世代を無効化し、再接続後も古い応答は反映しません。送信済みの変更要求は取り消せないため、復帰後に一覧を再取得して状態を確認します。

### 認証解除

見出し右端に認証解除を表示します。確認後に本人の管理用Per User資格情報だけを解除し、対象選択と一覧・結果を破棄して標準認証案内へ戻します。他の利用者や接続設定、更新対象アプリは変更しません。

## 出力・更新対象

- 画面への応答は、アプリ候補、ステージID・状態・有効期限、実行状態、確認日時、公開用の固定案内に限定します。
- API応答の鍵・秘密をLWC、DB、ログ、キャッシュへ保存しません。
- 更新対象は選択したアプリのOAuth資格情報と指定したステージだけです。

## 権限・実行条件

- `ManageExternalClientAppCredentials`とControllerへのアクセスが必要です。
- API認証ユーザーには`External Client App Developer`と`View Client Secret`が必要です。
- 外部クライアントアプリケーション設定の「REST APIを使用した外部クライアントアプリケーションのコンシューマーの秘密へのアクセスを許可」を有効にする必要があります。画面は設定を変更しません。
- 更新可能なのはローカルアプリで、管理用認証元は除外します。

### 管理用接続

1. 更新対象と別のローカルOAuthアプリ`ExternalClientAppManager`を作成し、`api`・`refresh_token`・`openid`スコープを設定します。
2. 同名のExternal Auth Identity Providerへ鍵・秘密を設定し、標準コールバックURLをアプリへ登録します。実値はソースへ保存しません。
3. OAuth Browser FlowのExternal Credentialを`ExternalClientAppManager`、Per User Principalを`ExternalClientAppUserPrincipal`として構成します。
4. Named Credentialを`ExternalClientAppManager`として導入先組織のMy Domainへ接続し、認証ヘッダーを生成します。本文へのトークン差し込みは使用しません。
5. 利用者本人へPrincipalアクセスと画面用権限セットを付与します。画面用権限セットは広い管理権限やPrincipalアクセスを自動追加しません。
6. 本人が画面から標準OAuth認証を完了します。APIの`userinfo`で現在のApex実行ユーザー・組織との一致を検証します。

## エラー処理

エラーはSLDSのエラー背景と枠、エラーアイコン、`role="alert"`で強調します。ステージ削除完了などの通常通知はエラー表示と区別します。

HTTP 403ではREST秘密アクセス設定と必要権限の確認場所を案内します。設定OFFと権限不足をHTTPステータスだけで断定しません。画面では設定値をMetadata APIから直接取得しません。

変更API送信前の拒否は`notStarted`としてサーバーの公開案内を表示し、結果不明のエラーと区別します。変更要求後の通信失敗・結果不明では成功を表示せず、後続処理を止めます。必須一覧の欠落や不正な配列も空一覧とは区別して停止します。APIの自由文や内部例外は公開しません。再実行は利用者が適用ボタンから開始し、毎回残存ステージを確認し、未適用だけを自動削除します。適用済みの旧コンシューマ鍵と秘密が残っている場合は手動削除するまで生成を停止します。

## テスト・確認観点

- `ExternalClientAppManagerControllerTest`：生成・適用・削除が独立していること、確認日時、変更前拒否、変更API失敗、変更後の再取得失敗とID・状態不一致、残存ステージがある場合の生成拒否、一件削除と状態変更拒否、公開操作と認証入口。通信モックでメソッド・対象パス・本文・順序と呼び出し回数を照合し、再送や後続操作がないことを確認します。
- `ExternalClientAppManagerServiceTest`：入力・対象・状態の検証、秘密を含まない公開情報。
- `ExternalClientAppManagerApiClientTest`：専用接続、本人確認、HTTP失敗の非公開化、不正JSON・オブジェクト以外の応答の拒否、通信例外と自動再送の禁止、不正パスの送信前拒否、標準認証の状態・URL境界。
- `externalClientAppManager.test.js`：認証前後、ID照合、確認・中止、二重送信防止、未適用だけの自動削除、旧コンシューマ鍵と秘密が残る場合の生成停止、手動削除の確認・中止、再表示でのAPI再取得、失敗時の停止、アクセシビリティ。
- `externalClientAppManagerLogic.test.js`：選択肢、公開属性の選別、自動更新のステージID・状態照合、内部例外非公開。

## 制約・注意事項

- 新しい値を取得・コピーするにはSalesforce標準設定画面を使用します。連携先の設定変更は利用者が行います。
- 適用と削除は連携への影響を確認して実行します。適用後も旧コンシューマ鍵と秘密は削除するまでステージに残ります。
- 既発行アクセストークン・更新トークン・全セッションの失効までは検証しません。
- APIの複数要求に対する排他制御やロールバックはなく、別管理者との同時操作は避けます。削除直前の状態照合だけで全競合を排除できるものではありません。
- 永続的な操作履歴や自動再試行は提供しません。再実行では未適用だけを自動削除し、適用済みの旧コンシューマ鍵と秘密は自動削除しません。

## 既知の差異・確認事項

設定のON/OFFは直接取得せず、参照APIの利用可否で操作を制御します。

### 管理用トークンの自動更新と本人確認

認証状態は保存済みのConfiguredを前提にせず、Named Credentialを使用した読み取り専用のREST API（`/services/data/v68.0/`）で接続を確認してから、`/services/oauth2/userinfo`で組織・ユーザーの一致を確認します。アクセストークンの更新はSalesforceの標準処理に委ねます。UserInfoの403だけを先に受けて再認証を求める経路は使用しません。

接続失敗時は、標準更新後の明示的な認証拒否または資格情報の未登録を認証要求として扱います。権限不足・通信障害・本人不一致は確認不能として停止します。資格情報を変更するPOST・PATCH・DELETEの独自再送は行いません。
