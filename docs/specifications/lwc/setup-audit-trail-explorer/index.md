# 設定変更履歴エクスプローラー

## 概要

Salesforce の設定変更履歴（`SetupAuditTrail`）を月単位で検索・分析し、履歴の検索結果、対象月全体、取得可能な全履歴を CSV で保存できます。

一覧・分析取得とCSV出力で未処理のApex例外が発生した場合、画面には操作別の案内を表示します。

## 目的・利用場面

日常の調査では、操作やユーザーで履歴を絞り込み、集計から該当する明細を開けます。監査提出資料には、Salesforce の設定画面「設定変更履歴を参照」の標準ダウンロードを使用します。

## 対象実装・メタデータ

- カスタムタブ `SetupAuditTrailExplorer` が画面の入口です。`setupAuditTrailExplorer.js` が取得と画面操作を制御し、`setupAuditTrailExplorerLogic.js` が表示値と CSV 明細を組み立てます。`setupAuditTrailChart.js` が集計結果を表示します。`setupAuditTrailExportModal.js` が標準モーダルでCSV出力の確認・進捗・エラーを表示し、`setupAuditTrailExportModalLogic.js` が対象範囲と件数の確認文を組み立てます。
- `SetupAuditTrailExplorerController` が一覧・集計・候補・CSV の要求を受け付け、`SetupAuditTrailExplorerSelector` が履歴を取得します。`SetupAuditTrailExplorerService` が期間・ページ境界の検証と結果の整形を行い、`SetupAuditTrailExplorerWrapper` が明細・集計・次ページの境界を返します。

## 入力

対象月は履歴タブと分析タブで共通です。月選択の直下でタブを切り替えます。履歴タブでは日付、ユーザー、名前空間、アクション、セクション、代理ユーザーを指定できます。検索条件と検索ボタンを一つの枠にまとめ、通常幅では6条件を3列2行に配置します。ルックアップで選択した値は同じ欄に読み取り専用で表示し、欄の右端の「×」で個別に解除できます。条件はその下の検索ボタンで適用します。絞り込み候補は月内の全候補から検索し、スクロール位置付近の最大16行を描画します。上下キーとスクロールで末尾まで選択できます。ユーザーと代理ユーザーの候補は1行目に氏名、2行目にログインユーザー名を表示し、どちらでも検索できます。ユーザーの氏名と ID があり、ログインユーザー名を取得できない場合は、2行目にユーザー ID を表示し、氏名または ID で検索できます。選択後はユーザー・代理ユーザーともに氏名を表示し、氏名を取得できない場合はログインユーザー名を表示します。月別 CSV は選択月の全履歴を対象とします。月別・全期間ともに、確認画面で初めて「出力」を押すとSalesforceから基準時刻を取得します。後続ページの取得と同じ確認画面での再試行にはその時刻を使い、月別の明細は選択月内に限定します。どちらも一覧の絞り込み条件から独立しています。

## 処理内容

一覧は作成日時と ID の降順で 1 ページ最大 1,000 件を取得します。表は先頭 50 行から表示し、スクロールが表示済みの末尾に達する前に、取得済みの明細を次の 50 行まで追加表示します。一覧の「アクション」列は、1行目に角括弧で囲んだ操作コード（`Action`）、次の行に同じ履歴の本文（`Display`）を表示します。片方が空なら値がある方だけを表示します。セクション検索では、取得元のページ境界を保持し、指定セクションに一致する行だけをブラウザーに返します。ユーザー検索は代理ログインも含めて履歴の作成者 ID を条件にします。分析はページ間で同じ集計軸の件数を合算します。最終ページでは取得した明細とページ位置から総ページ数を確定します。件数照会の結果が実際に移動できるページ数を下回る場合は、現在位置だけを表示します。絞り込み件数の取得に失敗した場合は、明細を表示したまま件数だけを再取得できます。移動先の履歴が保持期限などでなくなった場合は、元の検索時刻と絞り込み条件を維持し、残っている履歴の先頭ページと月別件数を再取得します。その間に開いた検索候補欄は入力文字を保持し、新しい候補で更新します。画面を離れた場合は候補欄を閉じ、戻った後に再び開いた時点で候補を表示します。CSVの明細は一覧と同じSOQLを使い、200件ずつ読み取ります。画面への応答は、1 回あたり最大 2,000 件と、本文などの合計 50 万文字を目安に分割取得します。続きがあれば最後に出力した履歴の作成日時と ID から再開し、全ページが揃った時点でダウンロードを開始します。

履歴の初期表示、月変更、検索では Salesforce 側で基準時刻を決め、履歴・月別件数・検索候補に適用します。再検索すると新しい変更が履歴に反映されます。直近に表示した5ページは明細を再利用し、それより古いページは保存した日時と ID の境界から取得します。

分析タブを初めて開くと、その時点の履歴検索の基準時刻を使い、選択月全体を集計します。集計完了後にグラフと基準時刻を表示します。同じ画面では、履歴の再検索、タブの往復、分析済みの月への再移動で月次分析を再取得しません。分析の途中で履歴タブに戻って検索しても、同じ月の集計は継続します。対象月を変更した場合や画面から離れた場合は、未完了の分析を破棄します。

タブを切り替えるときは履歴の検索条件とページ位置を保持します。分析の棒を選ぶと、その棒の条件で履歴の検索条件を置き換え、分析と同じ基準時刻で先頭ページを開きます。履歴と分析の基準時刻が同じ場合は月全体の分析結果を検索候補にも利用できます。

分析の日付は代理ログインも含めて実行ユーザーのタイムゾーンで集計し、日付の棒から同じ日の履歴を開けます。ユーザーグラフは履歴の作成者を集計し、氏名とログイン名が両方空の履歴は空欄の棒にまとめます。ユーザーの棒のツールチップと読み上げには、氏名と件数に加え、同姓同名のユーザーを区別できるログインユーザー名（取得できない場合はユーザー ID）を使います。

セクションで絞り込む一覧では、1ページ分の一致行が揃い次第表示します。次の一致が確認できたときに「次へ」を表示し、最終ページに到達すると総ページ数を確定します。分析のユーザーを選ぶと、履歴には対象ユーザーの条件が適用され、選択欄には棒と同じ氏名（氏名が空ならログインユーザー名）が表示されます。

## 出力・更新対象

履歴タブでは、表自体の高さを Salesforce の本文領域一画面分から 9.875rem（通常行で約5行分）を引いた高さに調整します。表までページをスクロールすると、その中で履歴の行をスクロールできます。表の下の「次へ」「前へ」を押すと、移動先の履歴を取得している間も表の高さを保ち、画面のスクロール位置を維持します。

「CSV出力 (全期間)」を選ぶと確認画面に「取得可能な全期間」と表示します。月別・全期間とも、CSV操作で対象期間の確認ダイアログを開き、「出力」で取得を開始します。取得済み件数とエラーはダイアログ内に表示し、全ページの取得が完了するとモーダルが閉じ、ダウンロードを開始します。「キャンセル」または Esc で中断できます。

履歴テーブル右下の「検索結果をCSV出力」は、表示中のページにかかわらず、最後に適用した条件と検索基準時刻で全ページの履歴を出力します。確認画面に対象月、適用済み条件、一致件数を表示します。セクションで絞り込む場合は一覧と同じ判定で一致 ID を確定し、その ID に対応する CSV 明細を分割取得します。件数が確認時と異なる場合は再検索を案内します。履歴が空のときはボタンが無効になります。

ファイル名は検索結果が `SetupAuditTrailSearchResultsYYYYMM.csv`、月別が `SetupAuditTrailMonthlyYYYYMM.csv`、全期間が `SetupAuditTrailAll.csv` です。YYYYMM は取得条件の対象年月です。

検索結果・月別・全期間のCSVは、ユーザーの言語設定にかかわらず出力できます。一覧とCSVの列名は、実行ユーザーの言語で取得したSalesforceの項目ラベルです。「ユーザー名」には参照先の `User.Username` のラベルを使います。月別・検索結果・全期間のCSVは7列です。「アクション」列に `Action`、「表示」列に `Display` をそれぞれ原文のまま出力します。各行には下表のAPI項目の値を使い、取得値が空の列は空欄にします。

いずれの CSV も BOM 付き UTF-8 です。レコードの区切りには LF を使い、セル内の改行は原文どおり保持し、セル内の引用符は二重にします。履歴の文字は Unicode のまま出力します。表計算ソフトでは、先頭が `=` などの値が数式として解釈される場合があります。原文を確認する場合は、CSV のインポートで各列を文字列として指定します。

| 列（日本語の例）               | 出力する値                                                                  |
| ------------------------------ | --------------------------------------------------------------------------- |
| 作成日                         | `CreatedDate` を実行ユーザーのタイムゾーンで表記。時は 0〜23、分と秒は 2 桁 |
| ユーザー名                     | `CreatedBy.Username`                                                        |
| ソースの名前空間プレフィックス | `ResponsibleNamespacePrefix`                                                |
| アクション                     | `Action`                                                                    |
| 表示                           | `Display`                                                                   |
| セクション                     | `Section`                                                                   |
| 代理ユーザー                   | `DelegateUser`                                                              |

## 権限・実行条件

タブと Apex コントローラーを利用でき、実行ユーザーが設定変更履歴を参照できることが必要です。`SalesforceApplicationUser` はタブを表示します。利用者にはプロファイルまたは権限セットで `SetupAuditTrailExplorerController` のクラスアクセスも付与します。Selector はユーザーモードで照会します。

## エラー処理

分析タブは、ページごとに集計が完了した件数を「分析中（○件集計済み）」と表示します。月変更や再試行では0件から数えます。分析、検索候補、検索対象IDは、続きとして取得した元ページが0件なら取得を中断します。セクションで絞り込んだ結果だけが0件のページは走査を続けます。一覧は対象IDと取得した明細のID・順序が揃ったページだけを表示します。

一覧・分析・検索候補・CSV のページ取得で一時的な通信障害が発生した場合は、同じ検索が続いている間に限り、失敗したページを同じ条件で一度再試行します。分析の取得に失敗したときは分析タブに再試行操作を表示します。履歴と分析の基準時刻が同じ場合は、月別件数の照会に失敗しても、完了した分析の合計を月別件数に利用します。CSV の全ページを取得できない場合はエラーを表示します。月別・全期間のCSVでは、続きがあると応答された直後のページが0件なら、保存を中止して再出力を案内します。先頭ページが0件なら、列名だけのCSVを保存します。取得中に画面を離れた場合は、その出力要求の応答を破棄します。

## 関連コンポーネント

提出用の標準 CSV は設定画面からダウンロードできます。[Salesforce ヘルプ「設定変更履歴の監視」](https://help.salesforce.com/s/articleView?id=admin_monitorsetup.htm&language=ja&type=5)

## テスト・確認観点

`setupAuditTrailExplorer.test.js` は各ダウンロード操作、ページ境界、ファイル名と CSV の内容を確認します。`setupAuditTrailExplorerLogic.test.js` は日付をまたぐ時刻、セル内改行、Unicode 文字を確認します。`SetupAuditTrailExplorerSelectorTest` と `SetupAuditTrailExplorerServiceTest` は検索条件とページ処理を検証します。

## 制約・注意事項

「CSV出力 (全期間)」では、初回の取得基準時刻より前の参照可能な全履歴を出力します。後続ページと再試行でも同じ基準時刻を使います。180日より古い履歴が取得可能な場合は、その履歴も含みます。履歴を長期保存する機能はありません。

## 標準CSVとの違い

Salesforceの標準CSVは会社名、自動化プロセス、代理ログインのユーザー名や権限セット変更の対象名を独自に表記する場合があります。本機能の一覧とCSVは各履歴の取得値を使うため、これらの表記は標準CSVと異なることがあります。
