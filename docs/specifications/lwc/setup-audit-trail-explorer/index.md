# 設定変更履歴エクスプローラー

## 概要

Salesforce の設定変更履歴（`SetupAuditTrail`）を月単位で検索・分析し、対象月または保持期間内の履歴を CSV で保存できます。

## 目的・利用場面

日常の調査では、操作やユーザーで履歴を絞り込み、集計から該当する明細を開けます。監査提出資料には、Salesforce の設定画面「設定変更履歴を参照」の標準ダウンロードを使用します。

## 対象実装・メタデータ

- カスタムタブ `SetupAuditTrailExplorer` が画面の入口です。`setupAuditTrailExplorer.js` が取得と画面操作を制御し、`setupAuditTrailExplorerLogic.js` が表示値と CSV 明細を組み立てます。`setupAuditTrailChart.js` が集計結果を表示します。
- `SetupAuditTrailExplorerController` が一覧・集計・候補・CSV の要求を受け付け、`SetupAuditTrailExplorerSelector` が履歴を取得します。`SetupAuditTrailExplorerService` が期間・ページ境界の検証と結果の整形を行い、`SetupAuditTrailExplorerWrapper` が明細・集計・次ページの境界を返します。

## 入力

一覧と分析は対象月、日付、ユーザー、名前空間、アクション、セクション、代理ユーザーを指定できます。検索条件と検索ボタンを一つの枠にまとめ、通常幅では6条件を3列2行に配置します。ルックアップで選択した値は同じ欄に読み取り専用で表示し、欄の右端の「×」で個別に解除できます。条件はその下の検索ボタンで適用します。ユーザーと代理ユーザーの候補は1行目に氏名、2行目にログインユーザー名を表示し、どちらでも検索できます。選択後はユーザー・代理ユーザーともに氏名を表示し、氏名を取得できない場合はログインユーザー名を表示します。月別 CSV は選択月の全履歴を対象とします。月別・全期間ともに、Salesforce が最初のページを取得する時刻を明細と作成者照合の上限にします。後続ページと再試行も同じ時刻を使い、月別の明細は選択月内に限定します。どちらも一覧の絞り込み条件から独立しています。

## 処理内容

一覧は作成日時と ID の降順で 1 ページ最大 1,000 件を取得します。表は先頭 50 行から表示し、表内をスクロールすると取得済みの明細を 50 行ずつ追加表示します。一覧のユーザーと代理ユーザーには氏名を表示し、氏名を特定できない場合は元の表記を使います。CSV のユーザー表記は独立して処理します。アクションには CSV と共通の表示規則を使います。セクション検索では、取得元のページ境界を保持し、指定セクションに一致する行だけをブラウザーに返します。ユーザー検索では作成者が一致する行と代理ログイン行を照合します。代理ログイン以外のアクションも指定され、セクションが未指定の場合は、作成者とアクションを直接指定して対象ページを取得します。代理ログインでは照合後のユーザーを使います。分析はページ間で同じ集計軸の件数を合算します。最終ページでは取得した明細とページ位置から総ページ数を確定します。件数照会の結果が実際に移動できるページ数を下回る場合は、現在位置だけを表示します。絞り込み件数の取得に失敗した場合は、明細を表示したまま件数だけを再取得できます。移動先の履歴が保持期限などでなくなった場合は、同じ確定条件の先頭ページを再取得します。複数ページでも同じ条件の分析が完了していれば、その合計件数を利用します。CSV はページ境界を引き継いで明細を取得し、全ページが揃った時点でダウンロードを開始します。

初期表示、月変更、検索のたびに Salesforce 側で基準時刻を決めます。履歴・月別件数・検索候補・分析はその時刻より前の履歴を使います。分析の棒から開く明細は同じ時刻を引き継ぎます。閲覧中に追加された履歴は再検索で反映します。直近に表示した5ページは再取得せず、それより古いページは保存した日時と ID の境界から再取得します。一覧と分析は、同じ検索条件で直近に照合した範囲を共有し、次ページに含まれる一致行も再利用します。検索条件が変わると明細と照合範囲を破棄します。月全体の検索候補と代理ログインの照合結果は同じ基準時刻のドリルダウンで引き継ぎ、再検索や月変更で取り直します。

セクションや代理ログインの照合が必要な一覧では、1ページ分の一致行が揃い次第表示します。次の一致が確認できたときに「次へ」を表示し、最終ページか分析の完了時に総ページ数を確定します。分析のユーザーを選ぶと、履歴には対象ユーザーの条件が適用され、選択欄には棒と同じ氏名（氏名が空ならログインユーザー名）が表示されます。

## 出力・更新対象

履歴タブでは、表自体の高さを Salesforce の本文領域一画面分から 9.875rem（通常行で約5行分）を引いた高さに調整します。表までページをスクロールすると、その中で履歴の行をスクロールできます。ページ送りは表の下に表示します。

月別・全期間とも、CSV操作で対象期間の確認ダイアログを開き、「出力」で取得を開始します。取得済み件数とエラーはダイアログ内に表示し、ダウンロード開始後に閉じます。「キャンセル」または Esc で中断できます。

ファイル名は月別が `SetupAuditTrailMonthly<開始時刻>.csv`、全期間が `SetupAuditTrailAll<開始時刻>.csv` です。開始時刻には、出力操作時に端末で取得した Unix タイムスタンプ（ミリ秒）を使用します。

両方の CSV は BOM 付き UTF-8 です。レコードとセル内の改行には LF を使い、セル内の引用符は二重にします。履歴の文字は Unicode のまま出力します。

| 列                             | 出力する値                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------- |
| 日付                           | `CreatedDate` を実行ユーザーのタイムゾーンで表記。時は 0〜23、分と秒は 2 桁                    |
| ユーザー                       | `CreatedBy.Username`。日本語では識別できた自動化プロセス・Salesforce側の作成者を標準表記で出力 |
| ソースの名前空間プレフィックス | `ResponsibleNamespacePrefix`                                                                   |
| アクション                     | `Display` の説明文。日本語の権限セット変更では確認済みの対象オブジェクト名を標準表記で出力     |
| セクション                     | `Section`                                                                                      |
| 代理ユーザー                   | `DelegateUser`                                                                                 |

## 権限・実行条件

タブと Apex コントローラーを利用でき、実行ユーザーが設定変更履歴を参照できることが必要です。`SalesforceApplicationUser` はタブを表示します。利用者にはプロファイルまたは権限セットで `SetupAuditTrailExplorerController` のクラスアクセスも付与します。Selector はユーザーモードで照会します。

## エラー処理

CSV の一時的な通信障害では、失敗したページを同じ境界から一度再試行します。全ページを取得できない場合はエラーを表示します。取得中に画面を離れた場合は、その出力要求の応答を破棄します。

## 関連コンポーネント

提出用の標準 CSV は設定画面からダウンロードできます。[Salesforce ヘルプ「設定変更履歴の監視」](https://help.salesforce.com/s/articleView?id=admin_monitorsetup.htm&language=ja&type=5)

## テスト・確認観点

`setupAuditTrailExplorer.test.js` は両方のダウンロード操作、ページ境界、ファイル名と CSV の内容を確認します。`setupAuditTrailExplorerLogic.test.js` は日付をまたぐ時刻、セル内改行、Unicode 文字を確認します。`SetupAuditTrailExplorerSelectorTest` と `SetupAuditTrailExplorerServiceTest` は検索条件とページ処理を検証します。

## 制約・注意事項

全期間は、その時点で Salesforce が保持し、実行ユーザーが取得できる期間です。履歴を長期保存する機能はありません。

## 既知の差異・確認事項

日本語の CSV では、自動化プロセスをユーザー種別で識別します。作成者のログイン名が空の場合は、保持期間内の直近 200 件の代理ユーザー付き内部操作（`BlackTabFrameworkActionRun`）から、「Salesforce 従業員が」で始まる本文に記録された作成者 ID と一致したときだけ「株式会社セールスフォース・ジャパン」と表示します。それ以外は空欄です。

権限セットのオブジェクト権限変更では、日本語の標準 CSV で確認した 14 種類の API 名を対象名の位置だけで置換します。未登録の対象名は原文を保持します。UTF-8 で保持できる原文の文字は、標準 CSV の文字コードで置き換わる場合があります。

代理ログインの作成者が代理ユーザー自身の場合は、保持期間内の代理ログイン・ログアウト履歴を出力ごとに一度照合します。日本語の本文に記録された対象表示名と代理ユーザーが一致するログインとログアウトが時系列で交互に並び、各ログインに対応する次のログアウトの作成者名が対象表示名と一致し、別の作成者 ID とログイン名を確認できた場合に、そのログイン名をログイン行の「ユーザー」に出力します。月別でも照合は月外を含みます。照合期間の端で片側しかない操作には API の作成者を使い、期間内の完了した組は個別に補正します。同じ操作の連続や同時刻など、対応順を特定できない場合は、その代理ユーザーと対象表示名の組で API の作成者を保持します。「代理ユーザー」列は履歴の値を使用します。
