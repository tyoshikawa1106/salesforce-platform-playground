# 最新レコードエクスポートスクリプト

## 概要

指定オブジェクトの項目を、指定ファイルの順でCSVへ出力する。最新1件を基準に空欄を補完するレコードフィールドプレビュー（縦型）と、最新から指定件数のレコードを補完せず取得する横型の2コマンドを提供する。`--record-type-id`を指定した場合だけ、取得・補完をそのレコードタイプに限定する。

## 目的・利用場面

レコードフィールドプレビューはデモ用の項目値を確認する用途。実データを読み取って補完し、架空の値は生成しない。最新レコードの空欄を別レコードから補完するため、全項目が同一レコードの実値ではない。横型は実レコードを行ごとに比較する用途で、空欄も実データのまま保持する。

## 対象実装・メタデータ

- [export-record-fields-preview.js](../../../../scripts/record-export/export-record-fields-preview.js): 縦型CSVの実行入口。
- [export-latest-records.js](../../../../scripts/record-export/export-latest-records.js): 横型CSVの実行入口。
- [export-runner.js](../../../../scripts/record-export/internal/export-runner.js): 引数、既存認証、組織確認、CLI実行、進捗表示、保存。
- [collector.js](../../../../scripts/record-export/internal/collector.js): 項目検証、最新順の選択、IDによる値照合、縦型の空欄補完、CSV変換。
- [query-client.js](../../../../scripts/record-export/internal/query-client.js): Composite APIによる読み取り、応答ファイル・APIページの検証。
- [preview-values.js](../../../../scripts/record-export/internal/preview-values.js): 直近レコードの一括補完、残項目のOR検索、指定順を維持した候補管理。
- [checkpoint.js](../../../../scripts/record-export/internal/checkpoint.js): 取得条件・対象ID・確定した値の保存、再開時の照合、同時実行の防止。
- [csv-spool.js](../../../../scripts/record-export/internal/csv-spool.js): ID別一時CSVへの退避、指定順の結合、完成ファイルの公開。
- [run-command.js](../../../../scripts/common/run-command.js): OS別の非同期CLI起動。
- [target-org.js](../../../../scripts/common/target-org.js): default target orgと組織種別の確認・表示。
- [approval.js](../../../../scripts/common/approval.js): 実行確認入力。

Salesforceメタデータの追加や変更は行わない。

## 入力

UTF-8のテキストファイルに、対象オブジェクト直下の項目API名を1行ずつ記載する。空行、行頭の`#`コメント、BOMを許容する。大小文字を区別せず重複を除き、最初に指定した順を保持する。関連項目パス・SOQL式は受け付けない。API名の出力表記はDescribe上の正規名を使用する。

```text
Phone
Name
PersonEmail
ContactCustomField__pc
```

| 引数                 | 内容                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `--target-org`       | aliasまたはusername。省略時はdefault target org                                                                  |
| `--record-type-id`   | 両コマンドで使用可能。012で始まる15桁または18桁のID。省略時はレコードタイプで絞り込まない                        |
| `--created-before`   | `YYYY-MM-DD`。日本時間の指定日午前0時より前の作成レコードに限定。当日を含まない。未指定は日付制限なし            |
| `--object`           | 対象オブジェクトAPI名。既定`Account`                                                                             |
| `--fields`           | 項目ファイル。既定`scripts/record-export/config/fields.txt`（実行ディレクトリに依存しない）                      |
| `--record-limit`     | 横型のみ。既定2,000件、許容範囲1〜10,000。縦型は最新1件固定でこの引数を受け付けない                              |
| `--fields-per-query` | 手動の項目数上限。省略時は全指定項目、指定時は1〜10,000。制限時はさらに自動分割                                  |
| `--resume`           | 元の`--output`と同じ取得条件を指定し、保存済みの範囲を復元して未処理項目から再開する。`--check-auth`とは併用不可 |
| `--output`           | 保存先。既定は`export-out/record-fields-preview-<実行時刻>.csv`または`export-out/records-<実行時刻>.csv`         |
| `--check-auth`       | 項目ファイル・確認入力・レコード取得・CSV保存なしで組織確認とDescribeを実行                                      |
| `--help`             | 実行方法を表示して終了                                                                                           |

日付指定時は対象ID選択・値取得・先読み・OR補完のすべてに `CreatedDate < 指定日午前0時のUTC日時` を適用する。例: `--created-before 2026-10-01` は `CreatedDate < 2026-09-30T15:00:00.000Z`。範囲内で最新順に取得し、項目順は変更しない。再開時は同じ日付指定が必要。日付未指定の既存再開記録はそのまま使用できる。

ファイルパスは実行ディレクトリ基準。`Account`や`__pc`による個人取引先への自動限定は行わない。レコードタイプ指定なしでは参照可能な全レコードを対象にし、指定時はプレビューの補完元を含めて同じタイプに限定する。`--check-auth`でも指定レコードタイプの所属をDescribeで検証する。

```sh
# 最新1件を基準に空欄を補完し、指定順の縦型CSVへ出力
npm run sf:export:record-fields-preview -- --object Account

# 最新から指定件数を補完せず、指定列順の横型CSVへ出力
npm run sf:export:records -- --object Account --record-limit 2000

# 指定レコードタイプだけから取得・補完（個人取引先のタイプを指定することも可能）
npm run sf:export:record-fields-preview -- --target-org <alias> --object Account --record-type-id <ID>

# 別のオブジェクト
npm run sf:export:records -- --object Contact --fields scripts/record-export/config/contact-fields.txt --record-limit 2000

# 接続・対象オブジェクトの確認のみ
npm run sf:export:records -- --check-auth
```

## 処理内容

1. 引数と項目ファイルを検証し、既存の出力先があれば停止する。
2. 組織を既存認証と照合し、alias・username・URL・組織種別を表示する。通常実行では取得範囲・件数・出力形式・ファイルを表示し、レコードタイプ指定時は取得と補完元を同じタイプに限定すると明示する。確認入力前に、縦型は「最新1件＋可能な空欄を補完 / デモ用値・縦型」、横型は最大件数と「補完なし / 実データ・横型」を1行で表示する。`y`または`Y`で承認された場合だけ進める。本番環境では追加確認する。
3. 表示したusernameへ接続先を固定し、Describeで項目・最新順の成立条件と指定レコードタイプの所属を確認する。Describeで確認できない項目はエラーを表示して検索から外し、確認できた項目の取得を続ける。未確認項目も指定位置は維持する。
4. `ORDER BY CreatedDate DESC NULLS LAST, Id DESC`で最新の対象レコードIDと作成日時を先に取得する。縦型は1件、横型は指定上限まで。同じ作成日時はId降順で順序を固定する。
5. 全対象ID・全指定項目で値取得を試みる。1件は`Id = ...`、複数件は`Id IN (...)`を使う。SOQL文字数超過・数式の複雑さ・応答サイズ超過時だけ範囲を縮小する。各応答をIDで照合し、指定項目順のCSV断片として一時保存する。項目グループ間で別レコードの値を混ぜない。
6. 横型はそのまま保存へ進む。縦型だけは空欄項目を次の手順で補完する。
7. 確認済み項目の取得と未確認項目の空セルが全指定位置に揃った場合に、一時CSVを対象ID順に連結して完成ファイルを排他的に公開し、件数と保存先を表示する。対象レコードなしはヘッダーのみ保存し、対象なしと表示する。

### 縦型の補完

最新レコードでNULL・空文字・構成要素がすべて空の複合値だけを補完対象とする。`false`と`0`は実値であり上書きしない。

filterableかつ非NULL比較が可能な空欄項目だけを補完対象とする。住所・位置情報の複合項目はfilterable=trueでも非NULL比較できないため補完対象外とし、構成項目はそれぞれの型・filterableで判定する。検索不可の項目は追加検索せず最新レコードの値を保持し、空欄の場合は`NOT_FILTERABLE`と表示する。

各取得グループで補完対象が複数ある場合は、まず新しいレコードから最大200件をまとめて取得する。これは全件走査を避ける先読み上限であり、Salesforceの項目数制限ではない。取得する列は補完可能な空欄項目と照合用IDだけとし、作成日時・Idの降順で各項目の最初の実値を採用する。応答サイズ超過時は取得件数を減らす。取得行数が上限未満ならその検索範囲を確認済みとして、残りは`NO_VALUE_FOUND`とする。補完対象が一項目だけなら先読みを省略する。

残った項目は `(FieldA != NULL OR FieldB != NULL)` の条件で最新1件を検索する。取得できた項目をSELECTとOR条件から外して繰り返し、ゼロ件なら残りを`NO_VALUE_FOUND`とする。日時・Idの境界条件は付けず、レコードタイプ条件はOR全体に適用する。文字数・複雑さ・サイズ制限、または検索タイムアウトでは項目を指定順の連続範囲に分割し、先頭側から処理する。一項目でも失敗する場合は停止する。通信・認証のエラーは再分割しない。

検索は並列化しない。候補値が後方の項目から見つかっても、結果表示・途中保存・CSVは指定項目順に確定する。途中で停止した場合は確定済みの先頭範囲だけを再開記録として使用し、未確定の候補は再検索する。全件探索や補完のページ送りは行わない。基準レコード自体は差し替えないが、検索では実行中に追加・更新された値も補完元になり得る。OR検索の負荷はデータ分布や実行計画に依存するため、常に高速化するとは保証しない。

補完検索で実値を取得できない場合は元の空欄を保持する。組織全体で未使用とは断定せず、実行ユーザーから参照できる範囲での結果とする。

### 進捗と接続

実行条件は「対象」の前と「出力先」の後に空行を入れて表示する。項目ファイルと出力先は実行ディレクトリからの相対パスで表示する。一括取得の開始時は「最新レコードを取得中」と最大件数だけを表示し、各項目を「値取得中」と列挙しない。未確認項目のエラーは先出しせず、取得結果・補完状況とともに指定順で表示する。横型は全対象レコードの取得後に各項目の結果を一度ずつ表示する。各項目の表示は項目番号・API名・状態の3列をタブで区切り、表計算ソフトへ貼り付けられる形式にする。縦型では状態に、取得成功、補完成功、登録レコードなし、補完対象外の理由を表示し、1項目1行で結果を残す。対話端末では補完中の項目を改行せず表示し、結果が返ったら同じ行を置き換える。リダイレクト時は制御文字や補完開始行を出さず、結果だけを記録する。分割取得後も項目番号はリセットしない。

Describeで確認できない項目は、指定順の項目番号とAPI名に「取得不可：API名が存在しない、または項目参照権限がありません」と付記して取得をスキップする。Describeだけでは両者を確定できないため、権限不足とは断定しない。非NULL条件で検索できないことは参照権限不足とは区別する。検索時のINVALID_FIELD・INSUFFICIENT_ACCESSでも対象項目の説明に参照権限の確認を案内して停止する。一括検索ではエラーの原因となった単一項目を特定したとは扱わない。

既存認証でSalesforce CLIを使用する。応答待ち中の定期的な実行中メッセージは表示しない。実値を端末へ表示せず、進捗表示のための追加API呼び出しは行わない。

CLIは非同期で待つが、問い合わせは逐次実行する。各CLI呼び出しの制限時間は2分。スクリプトによる待機終了は `CLI_TIMEOUT`、CLIの通信タイムアウトは `NETWORK_TIMEOUT`、Salesforceの検索タイムアウトは `QUERY_TIMEOUT` と区別する。失敗時は実測のCLI経過時間・終了コード・構造化された短い識別子を表示し、生のエラー本文は表示しない。補完検索の失敗は項目番号・API名・原因コード・補完経過時間を残して停止する。Describeの標準出力上限は64MiB。検索は`sf api request rest --stream-to-file`で応答を一時ファイルへ直接保存する。検索のAPIバージョンはDescribeの返却パスに合わせ、項目定義との不一致を防ぐ。バージョンを確認できない場合は検索を開始せず停止する。SOQLは同じAPIバージョンのCompositeリクエスト本文に読み取り専用のGETサブリクエストとして格納するため、外側のURLに長いSOQLを含めない。CLI内部で検索結果全件を自動取得・蓄積させない。

### 取得量の調整

固定100項目・200レコードの分割は行わない。生成したSOQL本文が100,000文字を超える場合は、送信前に上限内へ収まる最大の取得範囲を二分探索で計算する。全項目が1レコード分でも収まらない場合は項目を分割し、それ以外はID集合を分割する。WHEREやLIMITも含む実際の文字数を使う。`QUERY_TOO_COMPLICATED`の場合は項目を二分する。

APIが複数ページで結果を返した場合は`nextRecordsUrl`を使って取得する。1回の値取得について全ページの生JSONファイルサイズを合計し、64MiBを超えたらJSON読み込み前に打ち切り、対象レコードを二分して再取得する。1レコードでも超える場合は項目を二分する。各再試行では範囲が必ず縮小し、最小単位でも失敗すれば停止する。通常の値取得では認証・権限・タイムアウト・不完全応答は自動分割の対象にしない。複数項目の補完検索に限り、タイムアウト時も項目範囲を縮小する。

成功した範囲はIDごとのCSV断片として即座に退避する。メモリには全出力ではなく1回の取得結果とその変換分を保持する。最終CSVは64KiBのコピー用バッファで断片を連結する。APIの応答順によらず、対象ID順・指定項目順・全項目の存在を確認してから公開する。CSV再構築用の一時領域は通常終了と例外終了で削除する。再開用の確定断片は異常終了時に保持する。

## 出力・更新対象

### レコードフィールドプレビュー（縦型CSV）

1行＝1指定項目。行順は指定ファイルどおり。

| 列               | 内容                                                                                                                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FieldApiName`   | 項目API名                                                                                                                                                                                                               |
| `Label`          | 項目ラベル                                                                                                                                                                                                              |
| `Type`           | 項目の型                                                                                                                                                                                                                |
| `Value`          | 最新レコードの値、または補完した値                                                                                                                                                                                      |
| `Status`         | `LATEST`: 基準レコードの実値、`SUPPLEMENTED`: 別レコードから補完、`NO_VALUE_FOUND`: 補完検索で実値を取得できず、`NOT_FILTERABLE`: 非NULL条件で検索不可で補完未実施、`INVALID_FIELD`: Describeで確認できず取得をスキップ |
| `SourceRecordId` | 実値の取得元ID。値が見つからない場合は空欄                                                                                                                                                                              |

補完元IDは値の由来を示す固定の付帯列であり、項目行の並び順は変更しない。`Id`・`CreatedDate`の項目行は指定ファイルに記載された場合だけ出力する。

### 横型CSV

ヘッダーは指定項目のAPI名のみ。列順は指定ファイルどおり。1行＝1レコードで、選択時の作成日時降順を維持する。内部照合用の`Id`・`CreatedDate`を自動追加しない。出力したい場合だけ指定ファイルへ記載する。空欄を補完しない。

両形式とも、引用符と改行をCSVの規則でエスケープする。複合値はJSONで保存し、NULLは空セル、Booleanと数値は元の値を保持する。Salesforce側は読み取りのみ。既定の保存先はGit管理対象外で、既存ファイルを上書きしない。

## 権限・実行条件

リポジトリ指定のNode.jsと`sf api request rest --stream-to-file`を利用できるSalesforce CLI、既存認証、API・オブジェクト・項目・レコードへの参照権限が必要。ソート可能なCreatedDate・Idと検索可能なIdを持つオブジェクトに対応する。レコードタイプ指定時は検索可能なRecordTypeIdが必要であり、DescribeのrecordTypeInfosで対象オブジェクトに属するIDか確認する。15桁IDは大小文字を区別して18桁IDの先頭15桁と照合し、18桁IDは完全一致で照合する。レコード作成の可否を表すavailableだけでは読み取りを拒否しない。条件を満たさない場合は理由を表示して停止し、絞り込みを外して続行しない。

## エラー処理

- 終了コード`0`: 完了、対象なし、接続確認成功、または利用者の明示的な中止。
- 終了コード`1`: 未確認項目を空欄で残してCSVを保存した場合、または入力・接続・検索・ファイル操作の失敗。保存できた場合は出力先と項目エラー件数を表示する。その他の失敗ではCSVの完成は保証しない。

ファイル未検出、ディレクトリ指定、アクセス権限などは日本語で対処を案内する。CLI障害は`CLI_NOT_FOUND`、`CLI_ACCESS_DENIED`、`CLI_TIMEOUT`、`NETWORK_TIMEOUT`、`NETWORK_ERROR`、`QUERY_TIMEOUT`、`AUTH_FAILED`、`BUFFER_LIMIT`、既知のSOQLエラー名、または`CLI_FAILED`へ分類する。判別できない原因を推測せず、生のCLI応答・エラー本文を表示しない。サイズ超過時は、プレビューでは`--fields-per-query`または指定項目数の削減を案内し、横型では`--record-limit`または`--fields-per-query`の削減を案内する。

Describeで未確認の項目は両形式とも指定位置を空欄で残し、縦型では`INVALID_FIELD`と取得元なしを記録する。全項目が未確認でも対象レコードの選択だけ行い、値取得・補完クエリは送らない。対象レコードなしの場合はヘッダーのみ保存し、項目エラーは端末へ表示する。

取得途中は権限を制限した再開フォルダへ確定断片を保存し、完成CSVとは別の`.partial.csv`へ途中結果を公開する。確認済み項目の取得が成功するまで指定された完成ファイル名では公開しない。応答の途中打ち切り、項目欠落、ID重複、対象レコードの消失などを検出した場合も停止する。エラー後に別のレコードへ置き換えたり、取得失敗を空欄として隠したりしない。自動ログイン・再認証は行わない。

## 途中保存と再開

出力先が`export-out/account-preview.csv`なら、途中結果は`export-out/account-preview.partial.csv`、再開記録は`export-out/account-preview.csv.resume/`に保存する。縦型は一項目の補完・判定完了ごとに確定する。横型は取得範囲ごとにレコード別の断片を確定し、全項目が揃った連続するレコードだけを選択順で途中CSVへ追記する。横型の未完成行も再開記録には残る。

停止後は元と同じコマンド・引数に`--resume`を追加し、元の`--output`を指定する。自動採番した出力名を使った場合は、ログの出力名を`--output`に指定する。再開する前に前の処理が終了していることを確認する。別組織・ユーザー・オブジェクト・レコードタイプ・取得件数・作成日上限・項目順・項目定義への変更は拒否する。分割サイズは変更できる。

```sh
npm run sf:export:record-fields-preview -- --object Account --output export-out/account-preview.csv --resume
npm run sf:export:records -- --object Account --record-limit 2000 --output export-out/account-records.csv --resume
```

初回に選択したレコードIDと順序を保持し、最新レコードを選び直さない。保存済みの値は再検索せず復元する。未処理項目は再開時点の組織データを読むため、実行開始時点のスナップショットではない。未処理の対象レコードが削除された場合など、応答に欠落があれば停止する。

確定断片はJSONを一時ファイルへ書き、fsync後にrenameして公開する。未確定ファイルは再開時に使用しない。再開中は途中CSVを作業領域で復元してから公開し、破損を検出した場合は以前の途中CSVを保持する。再開記録と途中CSVは変更・削除しない。正常終了で完成CSVを公開した後に途中CSVと再開フォルダを削除する。

ロックで同時実行を拒否する。同じPCで強制終了したプロセスの終了を確認できた場合だけ、残ったロックを解除して再開する。別PCのロックや終了確認できないプロセスは自動解除しない。ロックの確認・回収・取得は排他区間で行う。この区間で強制終了して `lock-acquire` が残った場合は、同じ出力先の全処理が終了したことを確認してから、その空フォルダだけを削除して再開する。SIGKILLなどで残ったCSV再構築用の作業フォルダは再開記録とは別で、再開処理には利用しない。

この対応を入れる前に起動した処理には再開記録がないため、新しい再開機能は適用できない。

## 制約・注意事項

- 個人取引先のレコードタイプが複数あっても指定できるのは1種類。指定なしのプレビューでは法人・個人取引先など異なるタイプの値が混在する場合がある。
- 取得中の更新を同一時点へ固定するトランザクションではない。IDは一致させるが、別クエリの間に更新された値は混在し得る。
- 非NULL条件で検索不可の項目は補完しない。最新レコードで空欄の場合、他のレコードに値があっても空欄のまま出力する。
- サイズ超過・クエリ複雑さは範囲を縮小して再取得するため、制限に当たった場合はAPI呼び出しが増える。1レコード・1項目の失敗は解消できない。
- 一時ファイル用の空き容量が必要。完成ファイルの公開には同一ファイルシステム内のハードリンクを使用するため、対応するローカルファイルシステムが必要。強制終了や電源断では一時ファイルが残る場合がある。
- 特殊なWHERE条件が必須のオブジェクトには対応できない場合がある。
- マスキング・暗号化項目はAPIの応答をそのまま扱う。
- CSVは投入用データを生成する機能ではない。表計算ソフトで開く場合は、数式扱いになる値を文字列として読み込む。
