# 最新レコードエクスポートスクリプト

## 概要

指定オブジェクトの項目を、指定ファイルの順でCSVへ出力する。最新1件を基準に空欄を補完するレコードフィールドプレビュー（縦型）と、最新から指定件数のレコードを補完せず取得する横型の2コマンドを提供する。`--record-type-id`を指定した場合だけ、取得・補完をそのレコードタイプに限定する。

## 目的・利用場面

レコードフィールドプレビューはデモ用の項目値を確認する用途。メール・電話/FAX・選択リスト・住所・位置情報はDescribeだけでサンプル値を生成し、元データを取得しない。その他の型は実データを読み取って補完する。最新レコードの空欄を別レコードから補完するため、全項目が同一レコードの実値ではない。横型は実レコードを行ごとに比較する用途で、空欄も実データのまま保持する。

## 入力

UTF-8のテキストファイルに、対象オブジェクト直下の項目API名を1行ずつ記載する。空行、行頭の`#`コメント、BOMを許容する。大小文字を区別せず重複を除き、最初に指定した順を保持する。関連項目パス・SOQL式は受け付けない。API名の出力表記はDescribe上の正規名を使用する。

```text
Phone
Name
PersonEmail
ContactCustomField__pc
```

| 引数                 | 内容                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `--target-org`       | aliasまたはusername。省略時はdefault target org                                                                  |
| `--record-type-id`   | 両コマンドで使用可能。012で始まる15桁または18桁のID。省略時はレコードタイプで絞り込まない                        |
| `--created-before`   | `YYYY-MM-DD`。日本時間の指定日午前0時より前の作成レコードに限定。当日を含まない。未指定は日付制限なし            |
| `--object`           | 対象オブジェクトAPI名。既定`Account`                                                                             |
| `--fields`           | 項目ファイル。既定`scripts/record-export/config/fields.txt`（実行ディレクトリに依存しない）                      |
| `--record-limit`     | 横型のみ。既定2,000件、許容範囲1〜10,000。縦型は最新1件固定でこの引数を受け付けない                              |
| `--fields-per-query` | 手動の項目数上限。省略時は全指定項目、指定時は1〜10,000。制限時はさらに自動分割                                  |
| `--resume`           | 元の`--output`と同じ取得条件を指定し、保存済みの範囲を復元して未処理項目から再開する。`--check-auth`とは併用不可 |
| `--output`           | 保存先。既定は`export-out/record-fields-preview-<実行時刻>.csv`または`export-out/records-<実行時刻>.csv`         |
| `--check-auth`       | 項目ファイル・確認入力・レコード取得・CSV保存なしで組織確認とDescribeを実行                                      |
| `--help`             | 実行方法を表示して終了                                                                                           |

日付指定時は対象ID選択・値取得・個別補完のすべてに `CreatedDate < 指定日午前0時のUTC日時` を適用する。例: `--created-before 2026-10-01` は `CreatedDate < 2026-09-30T15:00:00.000Z`。範囲内で最新順に取得し、項目順は変更しない。再開時は同じ日付指定が必要。再開時は生成方針を含む同じ形式の記録を使用する。

ファイルパスは実行ディレクトリ基準。`Account`や`__pc`による個人取引先への自動限定は行わない。レコードタイプ指定なしでは参照可能な全レコードを対象にし、指定時はプレビューの補完元を含めて同じタイプに限定する。生成対象だけの場合はレコードを検索せず、レコードタイプ・作成日による絞り込みも使用しない。

```sh
# 最新1件を基準に空欄を補完し、指定順の縦型CSVへ出力
npm run sf:export:record-fields-preview -- --object Account

# 最新から指定件数を補完せず、指定列順の横型CSVへ出力
npm run sf:export:records -- --object Account --record-limit 2000

# 指定レコードタイプだけから取得・補完（個人取引先のタイプを指定することも可能）
npm run sf:export:record-fields-preview -- --target-org <alias> --object Account --record-type-id <ID>

# 別のオブジェクト
npm run sf:export:records -- --object Contact --fields scripts/record-export/config/contact-fields.txt --record-limit 2000

# 接続・対象オブジェクトの確認のみ
npm run sf:export:records -- --check-auth
```

## 処理内容

1. 引数と項目ファイルを検証し、既存の出力先があれば停止する。
2. 組織を既存認証と照合し、alias・username・URL・組織種別を表示する。通常実行では取得範囲・件数・出力形式・ファイルを表示し、レコードタイプ指定時は取得と補完元を同じタイプに限定すると明示する。確認入力前に、縦型は「対応する型はサンプル生成・その他は最新1件＋空欄補完 / デモ用値・縦型」、横型は最大件数と「補完なし / 実データ・横型」を1行で表示する。`y`または`Y`で承認された場合だけ進める。本番環境では追加確認する。
3. 表示したusernameへ接続先を固定し、Describeで項目と生成対象を判定する。実値の取得が必要な場合だけ、最新順の成立条件と指定レコードタイプの所属を確認する。Describeで確認できない項目はエラーを表示して検索から外し、確認できた項目の取得を続ける。未確認項目も指定位置は維持する。
4. 生成対象だけのプレビューはレコード検索を省略する。それ以外は`ORDER BY CreatedDate DESC NULLS LAST, Id DESC`で最新の対象レコードIDと作成日時を先に取得する。縦型は1件、横型は指定上限まで。同じ作成日時はId降順で順序を固定する。
5. 生成対象と未確認項目を除き、全対象ID・指定項目で値取得を試みる。1件は`Id = ...`、複数件は`Id IN (...)`を使う。SOQL文字数超過・数式の複雑さ・応答サイズ超過時だけ範囲を縮小する。各応答をIDで照合し、生成値も同じ項目順に組み合わせ、取得できた範囲ごとに再開データと途中CSVをまとめて保存する。項目グループ間で別レコードの値を混ぜない。
6. 横型はそのまま保存へ進む。縦型だけは空欄項目を次の手順で補完する。
7. 確認済み項目の取得と未確認項目の空セルが全指定位置に揃った場合に、一時CSVを対象ID順に連結して完成ファイルを排他的に公開し、件数と保存先を表示する。対象レコードなしはヘッダーのみ保存し、対象なしと表示する。

### サンプル生成（プレビューのみ）

Describeで確認した次の型と構成項目は、初回取得・補完の両方のクエリから除外する。実データが空欄かどうかも問い合わせない。

| 対象                            | 出力するサンプル                                                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| email                           | `demo@example.com`                                                                                                                         |
| phone（電話・FAX）              | `000-0000-0000`                                                                                                                            |
| picklist / multipicklist        | 有効な既定値。なければ有効な候補の先頭を一つ採用。表示ラベルではなくAPI値を使用                                                            |
| address / その構成項目          | 国・国コード`JP`、都道府県`東京都`、都道府県コード`13`、市区町村`サンプル市`、番地`サンプル町1-2-3`、郵便番号`000-0000`、位置精度`Address` |
| location / 緯度・経度の構成項目 | 緯度`35.681236`、経度`139.767125`。住所内の緯度・経度も同じ値                                                                              |

構成項目はDescribeの`compoundFieldName`で親の型を確認する。標準項目とカスタム項目に対応し、指定ファイルに構成項目だけがある場合も生成する。標準位置情報の`Latitude`・`Longitude`も、親がlocation型と確認できる場合に生成する。同名の通常数値項目だけでは生成対象にしない。項目名に「住所」や「電話」が含まれるだけのテキスト型は対象にしない。未知の構成項目は実値を取得せず、空欄と「サンプル未生成：構成項目に対応する値なし」を出す。有効な選択肢がなければ空欄と「サンプル未生成：有効な選択肢なし」を出す。生成値は「サンプル生成」とし、`SourceRecordId`は空欄にする。

生成値はレコードタイプや連動選択リストの制約では絞り込まない。参照用のサンプルであり、そのまま投入可能なデータを保証しない。途中CSV・完成CSV・再開データに生成対象の元の値は保存しない。生成対象だけなら対象レコードが存在しなくてもCSVを作成する。検索が必要な項目を含み対象レコードがない場合は、従来どおりヘッダーのみを保存する。横型にはこの生成を適用しない。

### 縦型の補完

生成対象を除き、最新レコードでNULL・空文字・構成要素がすべて空の値だけを補完対象とする。`false`と`0`は実値であり上書きしない。

filterableかつ非NULL比較が可能な空欄項目だけを補完対象とする。長文など検索不可の項目は追加検索せず最新レコードの値を保持し、空欄の場合は「補完対象外：非NULL条件で検索不可」と表示する。

最初に最新1件の全指定項目を取得し、初回取得結果をすべて途中CSVへ反映する。分割取得中には補完検索を開始しない。検索可能な空欄は`PENDING_SUPPLEMENT`（補完待ち）で保存する。全項目の初回取得・保存後、補完待ちの項目だけを指定順に非NULL検索し、CSVの同じ行を置き換える。直近200件を追加取得する段階は設けない。

残った項目は一項目ずつ `Field != NULL`・最新順・`LIMIT 1`の独立したSOQLとし、最大5本を一つのComposite通信にまとめる。`collateSubrequests=false`で指定順に実行し、`allOrNone=false`で一項目の検索エラーを他項目へ波及させない。応答のreferenceIdを要求と照合し、値あり・0件・エラーを各項目で独立して確定する。確定した項目を再検索しない。OR条件は使わない。

一通信（最大5検索）の応答待ち上限は60秒。問い合わせは並列化しない。時間超過、通信障害、CLI失敗、検索エラー、サイズ・複雑さの制限は`SKIPPED_<原因コード>`として保存し、後続項目へ進む。自動再試行は行わない。通信全体が失敗した場合は、その通信の全対象を取得失敗として記録する。認証・API利用上限・CLI起動不能・保存障害・応答の不整合は途中保存して停止する。エラー応答の`name`・`code`・`errorCode`と既存の2段階までの`cause`を同じ分類に使い、自由文から認証切れを推測しない。追加の認証確認通信は行わない。

補完結果は指定順に表示・保存し、CSVの元の行を置き換える。保存済みの値あり・0件・検索失敗は再検索せず、未保存の項目だけを再開する。全件探索や補完のページ送りは行わない。基準レコードは差し替えないが、補完は検索時点のデータを参照する。まとめるのはCLI起動と通信であり、項目ごとの検索本数は減らない。

補完検索で実値を取得できない場合は元の空欄を保持する。組織全体で未使用とは断定せず、実行ユーザーから参照できる範囲での結果とする。

### 進捗と接続

実行条件は「対象」の前と「出力先」の後に空行を入れて表示する。項目ファイルと出力先は実行ディレクトリからの相対パスで表示する。一括取得の開始時は「最新レコードを取得中」と最大件数だけを表示し、各項目を「値取得中」と列挙しない。未確認項目のエラーは先出しせず、取得結果・補完状況とともに指定順で表示する。横型は全対象レコードの取得後に各項目の結果を一度ずつ表示する。各項目の表示は項目番号・API名・状態の3列をタブで区切り、表計算ソフトへ貼り付けられる形式にする。縦型の初回取得では全項目を指定順に表示し、検索可能な空欄には「空欄・補完待ち」と表示する。初回取得完了後は補完対象だけを指定順に表示し、補完成功・登録レコードなし・検索失敗を通知する。初回取得と補完は開始メッセージで区別する。対話端末では保存後の残件数を同じ行で更新し、次の検索案内や項目結果で置き換える。5項目ごとの進捗行や、検索完了だけの行は残さない。リダイレクト時も検索状況と確定結果を記録するが、端末制御文字は出さない。初回取得は全指定項目数、補完はその実行で補完する項目数を分母にし、それぞれ1から番号を付ける。CSVの行順は変更しない。

Describeで確認できない項目は、指定順の項目番号とAPI名に「取得不可：API名が存在しない、または項目参照権限がありません」と付記して取得をスキップする。Describeだけでは両者を確定できないため、権限不足とは断定しない。非NULL条件で検索できないことは参照権限不足とは区別する。検索時のINVALID_FIELD・INSUFFICIENT_ACCESSでも対象項目の説明に参照権限の確認を案内する。補完中ならスキップとし、基準レコードの値取得中なら停止する。一括検索ではエラーの原因となった単一項目を特定したとは扱わない。

既存認証でSalesforce CLIを使用する。全指定項目の初回保存後に「初回取得完了」と補完待ち件数を表示する。補完開始時は補完対象件数、通信開始時は対象のAPI名と補完の残件数を表示する。応答待ち中は10秒ごとに経過時間と残り待機上限を表示する。保存済みの結果を反映するときは検索中と表示しない。実値を端末へ表示せず、進捗表示のための追加API呼び出しは行わない。

CLIは非同期で待つが、問い合わせは逐次実行する。通常のCLI呼び出しの制限時間は2分。補完は前述の合計60秒の残り時間を使う。スクリプトによる待機終了は `CLI_TIMEOUT`、CLIの通信タイムアウトは `NETWORK_TIMEOUT`、Salesforceの検索タイムアウトは `QUERY_TIMEOUT` と区別する。失敗時は実測のCLI経過時間・終了コード・応答形式・標準エラーの有無・構造化された短い識別子を表示し、生のエラー本文は表示しない。未知の元エラーコードも形式を検証して診断へ残し、汎用分類コードへの変換で捨てない。API応答がある場合はHTTPステータスも記録する。CLIが入れ子の原因コードを返した場合も既知の通信エラーを分類する。検索のCLI失敗は終了時にも「CLI失敗の診断」として同じ診断ごとの発生回数を表示する。スキップされた空欄は値の有無を未確認であり、値なしとは扱わない。補完の検索失敗は再試行せず、理由を表示して保存する。補完スキップは項目番号・API名・原因コードを表示し、CSVには「補完スキップ：日本語の理由（原因コード）」として保存する。同じまとめ検索でスキップした項目には、失敗した検索の実測時間を共通して表示する。Describeの標準出力上限は64MiB。検索は`sf api request rest --json`の通常受信を使い、CLIが受信完了または通信エラーを返すまで待つ。検索の標準出力も64MiBまでとし、受信上限を超えた場合は既存の分割処理へ渡す。検索のAPIバージョンはDescribeの返却パスに合わせ、項目定義との不一致を防ぐ。バージョンを確認できない場合は検索を開始せず停止する。SOQLは同じAPIバージョンのCompositeリクエスト本文に読み取り専用のGETサブリクエストとして格納するため、外側のURLに長いSOQLを含めない。CLI内部で全ページを自動取得させず、一回の応答と全ページの合計を制限する。

### 取得量の調整

固定100項目・200レコードの分割は行わない。生成したSOQL本文が100,000文字を超える場合は、送信前に上限内へ収まる最大の取得範囲を二分探索で計算する。全項目が1レコード分でも収まらない場合は項目を分割し、それ以外はID集合を分割する。WHEREやLIMITも含む実際の文字数を使う。`QUERY_TOO_COMPLICATED`の場合は項目を二分する。

APIが複数ページで結果を返した場合は`nextRecordsUrl`を使って取得する。1回の値取得についてCLI標準出力を64MiBに制限し、解析した全ページのJSONサイズの合計も64MiBを超えたら打ち切り、対象レコードを二分して再取得する。1レコードでも超える場合は項目を二分する。各再試行では範囲が必ず縮小し、最小単位でも失敗すれば停止する。通常の値取得では認証・権限・タイムアウト・不完全応答は自動分割の対象にしない。補完の検索失敗は再分割・再試行せず、取得失敗として保存する。

成功した範囲はIDごとのCSV断片として即座に退避する。メモリには全出力ではなく1回の取得結果とその変換分を保持する。最終CSVは64KiBのコピー用バッファで断片を連結する。APIの応答順によらず、対象ID順・指定項目順・全項目の存在を確認してから公開する。CSV再構築用の一時領域は通常終了と例外終了で削除する。再開用の確定断片は異常終了時に保持する。

## 出力・更新対象

### レコードフィールドプレビュー（縦型CSV）

1行＝1指定項目。行順は指定ファイルどおり。

| 列               | 内容                                                   |
| ---------------- | ------------------------------------------------------ |
| `FieldApiName`   | 項目API名                                              |
| `Label`          | 項目ラベル                                             |
| `Type`           | 項目の型                                               |
| `Value`          | 生成したサンプル値、最新レコードの値、または補完した値 |
| `Status`         | 日本語の処理結果。下表を参照                           |
| `SourceRecordId` | 実値は取得元ID。生成値・空欄・検索失敗は空欄           |
| `エラー詳細`     | 補完スキップの診断情報。成功・値なし・未処理は空欄     |

途中CSV・完成CSVのステータスは共通の日本語で出力する。補完をスキップした項目の「エラー詳細」には、取得できた元エラーコード・HTTPステータス・CLI終了コード・経過時間を保存する。情報が得られなかったものは推測せず、詳細がないことを示す。診断は途中保存・再開でも復元する。以前の再開記録に診断がなければ、その詳細は復元できない。再開データの内部コードは変更しない。

| 内部コード             | CSVの表示                                                   |
| ---------------------- | ----------------------------------------------------------- |
| `NOT_PROCESSED`        | 未処理                                                      |
| `LATEST`               | 取得成功                                                    |
| `SUPPLEMENTED`         | 補完成功                                                    |
| `NO_VALUE_FOUND`       | 登録レコードなし                                            |
| `NOT_FILTERABLE`       | 補完対象外：非NULL条件で検索不可                            |
| `INVALID_FIELD`        | 取得不可：API名が存在しない、または項目参照権限がありません |
| `PENDING_SUPPLEMENT`   | 補完待ち                                                    |
| `GENERATED`            | サンプル生成                                                |
| `NO_PICKLIST_VALUE`    | サンプル未生成：有効な選択肢なし                            |
| `NO_SAMPLE_VALUE`      | サンプル未生成：構成項目に対応する値なし                    |
| `SKIPPED_<原因コード>` | 補完スキップ：日本語の理由（原因コード）                    |

スキップの例は「補完スキップ：検索タイムアウト（QUERY_TIMEOUT）」。失敗理由と調査用の原因コードを併記し、登録レコードが存在しない場合と区別する。

補完元IDは値の由来を示す固定の付帯列であり、項目行の並び順は変更しない。`Id`・`CreatedDate`の項目行は指定ファイルに記載された場合だけ出力する。

### 横型CSV

ヘッダーは指定項目のAPI名のみ。列順は指定ファイルどおり。1行＝1レコードで、選択時の作成日時降順を維持する。内部照合用の`Id`・`CreatedDate`を自動追加しない。出力したい場合だけ指定ファイルへ記載する。空欄を補完しない。

両形式とも、引用符と改行をCSVの規則でエスケープする。複合値はJSONで保存し、NULLは空セル、Booleanと数値は元の値を保持する。Salesforce側は読み取りのみ。既定の保存先はGit管理対象外で、既存ファイルを上書きしない。

## 権限・実行条件

リポジトリ指定のNode.jsと`sf api request rest --json`を利用できるSalesforce CLI、既存認証、API・オブジェクト・項目・レコードへの参照権限が必要。ソート可能なCreatedDate・Idと検索可能なIdを持つオブジェクトに対応する。レコードタイプ指定時は検索可能なRecordTypeIdが必要であり、DescribeのrecordTypeInfosで対象オブジェクトに属するIDか確認する。15桁IDは大小文字を区別して18桁IDの先頭15桁と照合し、18桁IDは完全一致で照合する。レコード作成の可否を表すavailableだけでは読み取りを拒否しない。条件を満たさない場合は理由を表示して停止し、絞り込みを外して続行しない。

## エラー処理

- 終了コード`0`: 完了、対象なし、接続確認成功、または利用者の明示的な中止。
- 終了コード`1`: 未確認項目を空欄で残してCSVを保存した場合、または入力・接続・検索・ファイル操作の失敗。保存できた場合は出力先と項目エラー件数を表示する。その他の失敗ではCSVの完成は保証しない。

ファイル未検出、ディレクトリ指定、アクセス権限などは日本語で対処を案内する。CLI障害は`CLI_NOT_FOUND`、`CLI_ACCESS_DENIED`、`CLI_TIMEOUT`、`NETWORK_TIMEOUT`、`NETWORK_ERROR`、`QUERY_TIMEOUT`、`AUTH_FAILED`、`BUFFER_LIMIT`、既知のSOQLエラー名、または`CLI_FAILED`へ分類する。判別できない原因を推測せず、生のCLI応答・エラー本文を表示しない。サイズ超過時は、プレビューでは`--fields-per-query`または指定項目数の削減を案内し、横型では`--record-limit`または`--fields-per-query`の削減を案内する。

Describeで未確認の項目は両形式とも指定位置を空欄で残し、縦型では「取得不可：API名が存在しない、または項目参照権限がありません」と取得元なしを記録する。全項目が未確認でも対象レコードの選択だけ行い、値取得・補完クエリは送らない。対象レコードなしの場合はヘッダーのみ保存し、項目エラーは端末へ表示する。

取得途中は権限を制限した再開フォルダへ確定断片を保存し、完成CSVとは別の`.partial.csv`へ途中結果を公開する。基準レコードの値取得と各項目の判定が完了するまで、指定された完成ファイル名では公開しない。補完スキップがあっても完成CSVを保存し、件数を案内して終了コード1を返す。これは処理途中の中断とは異なり、再開記録は正常な保存完了時に削除する。応答の途中打ち切り、項目欠落、ID重複、対象レコードの消失などを検出した場合も停止する。エラー後に別のレコードへ置き換えたり、取得失敗を空欄として隠したりしない。自動ログイン・再認証は行わない。

## 途中保存と再開

出力先が`export-out/account-preview.csv`なら、途中結果は`export-out/account-preview.partial.csv`、再開記録は`export-out/account-preview.csv.resume/`に保存する。縦型の途中CSVは開始時から全指定項目の行を指定順で用意し、未処理行は「未処理」とする。未処理行は取得済み件数や再開位置には含めない。縦型の初回取得は取得範囲ごとに一度だけ再開記録を確定する。補完結果は一項目ずつ確定する。途中CSVは原則5項目ごと、または前回公開から1秒以上経過後の保存時に、既存の行を結果で更新する。次の補完通信前と中断時にも最新の確定結果を反映する。全行を更新する際も一定サイズのバッファで連結し、公開中のCSVを途中で切り詰めない。補完結果の途中CSV反映は通信単位の終了・中断時にまとめて元の行を更新する。縦型CSV断片は項目位置ごとに保持し、更新後も一定サイズのバッファで指定順に連結する。横型は取得範囲ごとにレコード別の断片を確定し、全項目が揃った連続するレコードだけを選択順で途中CSVへ追記する。横型の未完成行も再開記録には残る。

停止時には、接続先・オブジェクト・項目ファイル・出力先・絞り込み・取得件数を埋め込んだ`npm run ... --resume`コマンドを表示する。同じ作業ディレクトリでその行をコピーして実行する。macOS/Linuxはsh互換シェル、WindowsはPowerShell用の引用形式で出力する。再開する前に前の処理が終了していることを確認する。別組織・ユーザー・オブジェクト・レコードタイプ・取得件数・作成日上限・項目順・項目定義への変更は拒否する。分割サイズは変更できる。

```sh
npm run sf:export:record-fields-preview -- --object Account --output export-out/account-preview.csv --resume
npm run sf:export:records -- --object Account --record-limit 2000 --output export-out/account-records.csv --resume
```

初回に選択したレコードIDと順序を保持し、最新レコードを選び直さない。生成だけの場合も同じ保存位置を復元する。保存済みの値と確定したスキップ理由は再検索せず、残りの初回取得後に未検索の補完待ちだけを処理する。プレビューはサンプル生成方針を含むversion 2の再開記録を使用する。旧版の元データが混ざることを防ぐため、旧版プレビューの再開記録は受け付けず、別の出力先で新規実行する。生成する候補値が変わった場合も再開を拒否する。横型の再開形式は変更しない。未処理項目は再開時点の組織データを読み、実行開始時点のスナップショットとはしない。対象レコードの消失や応答の欠落は停止する。

確定断片はJSONを一時ファイルへ書き、fsync後にrenameして公開する。未確定ファイルは再開時に使用しない。再開中は途中CSVを作業領域で復元してから公開し、破損を検出した場合は以前の途中CSVを保持する。再開記録と途中CSVは変更・削除しない。正常終了で完成CSVを公開した後に途中CSVと再開フォルダを削除する。

ロックで同時実行を拒否する。同じPCで強制終了したプロセスの終了を確認できた場合だけ、残ったロックを解除して再開する。別PCのロックや終了確認できないプロセスは自動解除しない。ロックの確認・回収・取得は排他区間で行う。この区間で強制終了して `lock-acquire` が残った場合は、同じ出力先の全処理が終了したことを確認してから、その空フォルダだけを削除して再開する。SIGKILLなどで残ったCSV再構築用の作業フォルダは再開記録とは別で、再開処理には利用しない。

生成対象以外の氏名・自由記述・参照IDなどは実データのまま出力する。このプレビューを完全に匿名化されたデータとは扱わない。

## 制約・注意事項

- 個人取引先のレコードタイプが複数あっても指定できるのは1種類。指定なしのプレビューでは法人・個人取引先など異なるタイプの値が混在する場合がある。
- 取得中の更新を同一時点へ固定するトランザクションではない。IDは一致させるが、別クエリの間に更新された値は混在し得る。
- 非NULL条件で検索不可の項目は補完しない。最新レコードで空欄の場合、他のレコードに値があっても空欄のまま出力する。
- サイズ超過・クエリ複雑さは範囲を縮小して再取得するため、制限に当たった場合はAPI呼び出しが増える。1レコード・1項目の失敗は解消できない。
- 一時ファイル用の空き容量が必要。完成ファイルの公開には同一ファイルシステム内のハードリンクを使用するため、対応するローカルファイルシステムが必要。強制終了や電源断では一時ファイルが残る場合がある。
- 特殊なWHERE条件が必須のオブジェクトには対応できない場合がある。
- マスキング・暗号化項目はAPIの応答をそのまま扱う。
- CSVは投入用データを生成する機能ではない。表計算ソフトで開く場合は、数式扱いになる値を文字列として読み込む。
