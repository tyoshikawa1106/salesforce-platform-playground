# 最新レコードエクスポートスクリプト

## 概要

指定オブジェクトの項目を、指定ファイルの順でCSVへ出力する。最新1件を基準に空欄を補完するレコードフィールドプレビュー（縦型）と、最新から指定件数のレコードを補完せず取得する横型の2コマンドを提供する。`--record-type-id`を指定した場合だけ、取得・補完をそのレコードタイプに限定する。

## 目的・利用場面

レコードフィールドプレビューはデモ用の項目値を確認する用途。実データを読み取って補完し、架空の値は生成しない。最新レコードの空欄を別レコードから補完するため、全項目が同一レコードの実値ではない。横型は実レコードを行ごとに比較する用途で、空欄も実データのまま保持する。

## 対象実装・メタデータ

- [export-record-fields-preview.js](../../../../scripts/record-export/export-record-fields-preview.js): 縦型CSVの実行入口。
- [export-latest-records.js](../../../../scripts/record-export/export-latest-records.js): 横型CSVの実行入口。
- [export-runner.js](../../../../scripts/record-export/internal/export-runner.js): 引数、既存認証、組織確認、CLI実行、進捗表示、保存。
- [collector.js](../../../../scripts/record-export/internal/collector.js): 項目検証、最新順の選択、IDによる値照合、縦型の空欄補完、CSV変換。
- [query-client.js](../../../../scripts/record-export/internal/query-client.js): Composite APIによる読み取り、応答ファイル・APIページの検証。
- [csv-spool.js](../../../../scripts/record-export/internal/csv-spool.js): ID別一時CSVへの退避、指定順の結合、完成ファイルの公開。
- [run-command.js](../../../../scripts/common/run-command.js): OS別の非同期CLI起動。
- [target-org.js](../../../../scripts/common/target-org.js): default target orgと組織種別の確認・表示。
- [approval.js](../../../../scripts/common/approval.js): 実行確認入力。

Salesforceメタデータの追加や変更は行わない。

## 入力

UTF-8のテキストファイルに、対象オブジェクト直下の項目API名を1行ずつ記載する。空行、行頭の`#`コメント、BOMを許容する。大小文字を区別せず重複を除き、最初に指定した順を保持する。関連項目パス・SOQL式は受け付けない。API名の出力表記はDescribe上の正規名を使用する。

```text
Phone
Name
PersonEmail
ContactCustomField__pc
```

| 引数                 | 内容                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| `--target-org`       | aliasまたはusername。省略時はdefault target org                                                          |
| `--record-type-id`   | 両コマンドで使用可能。012で始まる15桁または18桁のID。省略時はレコードタイプで絞り込まない                |
| `--object`           | 対象オブジェクトAPI名。既定`Account`                                                                     |
| `--fields`           | 項目ファイル。既定`fields.txt`                                                                           |
| `--record-limit`     | 横型のみ。既定2,000件、許容範囲1〜10,000。縦型は最新1件固定でこの引数を受け付けない                      |
| `--fields-per-query` | 手動の項目数上限。省略時は全指定項目、指定時は1〜10,000。制限時はさらに自動分割                          |
| `--output`           | 保存先。既定は`export-out/record-fields-preview-<実行時刻>.csv`または`export-out/records-<実行時刻>.csv` |
| `--check-auth`       | 項目ファイル・確認入力・レコード取得・CSV保存なしで組織確認とDescribeを実行                              |
| `--help`             | 実行方法を表示して終了                                                                                   |

ファイルパスは実行ディレクトリ基準。`Account`や`__pc`による個人取引先への自動限定は行わない。レコードタイプ指定なしでは参照可能な全レコードを対象にし、指定時はプレビューの補完元を含めて同じタイプに限定する。`--check-auth`でも指定レコードタイプの所属をDescribeで検証する。

```sh
# 最新1件を基準に空欄を補完し、指定順の縦型CSVへ出力
npm run sf:export:record-fields-preview -- --object Account --fields fields.txt

# 最新から指定件数を補完せず、指定列順の横型CSVへ出力
npm run sf:export:records -- --object Account --fields fields.txt --record-limit 2000

# 指定レコードタイプだけから取得・補完（個人取引先のタイプを指定することも可能）
npm run sf:export:record-fields-preview -- --target-org <alias> --object Account --fields export-out/fields.txt --record-type-id <ID>

# 別のオブジェクト
npm run sf:export:records -- --object Contact --fields export-out/contact-fields.txt --record-limit 2000

# 接続・対象オブジェクトの確認のみ
npm run sf:export:records -- --check-auth
```

## 処理内容

1. 引数と項目ファイルを検証し、既存の出力先があれば停止する。
2. 組織を既存認証と照合し、alias・username・URL・組織種別を表示する。通常実行では取得範囲・件数・出力形式・ファイルを表示し、レコードタイプ指定時は取得と補完元を同じタイプに限定すると明示する。縦型は「空欄は非NULL条件で検索可能な項目だけ最新の非NULL値で補完」、横型は「空欄は補完しない」と確認入力前に明示する。`y`または`Y`で承認された場合だけ進める。本番環境では追加確認する。
3. 表示したusernameへ接続先を固定し、Describeで項目・最新順の成立条件と指定レコードタイプの所属を確認する。指定項目に不存在・参照不可があればまとめて表示し、検索前に停止する。
4. `ORDER BY CreatedDate DESC NULLS LAST, Id DESC`で最新の対象レコードIDと作成日時を先に取得する。縦型は1件、横型は指定上限まで。同じ作成日時はId降順で順序を固定する。
5. 全対象ID・全指定項目で値取得を試みる。1件は`Id = ...`、複数件は`Id IN (...)`を使う。SOQL文字数超過・数式の複雑さ・応答サイズ超過時だけ範囲を縮小する。各応答をIDで照合し、指定項目順のCSV断片として一時保存する。項目グループ間で別レコードの値を混ぜない。
6. 横型はそのまま保存へ進む。縦型だけは空欄項目を次の手順で補完する。
7. 全取得が成功し全指定項目が揃った場合に、一時CSVを対象ID順に連結して完成ファイルを排他的に公開し、件数と保存先を表示する。対象レコードなしはヘッダーのみ保存し、対象なしと表示する。

### 縦型の補完

最新レコードでNULL・空文字・構成要素がすべて空の複合値だけを補完対象とする。`false`と`0`は実値であり上書きしない。

filterableかつ非NULL比較が可能な空欄項目は、非NULL条件と作成日時・Idの降順で最新1件を検索する。日時・Idの境界条件は付けず、レコードタイプ指定時はその条件を適用する。住所・位置情報の複合項目はfilterable=trueでも非NULL比較できないため補完対象外とする。構成項目はそれぞれの型・filterableで判定する。検索不可の項目は追加検索せず最新レコードの値を保持し、空欄の場合は`NOT_FILTERABLE`と表示する。個別検索で実値が得られない場合は`NO_VALUE_FOUND`とする。全件探索や補完のページ送りは行わない。基準レコード自体は差し替えないが、個別検索では実行中に追加・更新された値も補完元になり得る。

補完検索で実値を取得できない場合は元の空欄を保持する。組織全体で未使用とは断定せず、実行ユーザーから参照できる範囲での結果とする。

### 進捗と接続

既存認証でSalesforce CLIを使用する。組織設定・組織一覧・Describe・検索の応答待ち中は、30秒ごとに処理名・そのCLI呼び出しの経過秒数・ローカル日時を表示する。確認入力中と終了後にはタイマーを残さない。実値を端末へ表示せず、進捗表示のための追加API呼び出しは行わない。

CLIは非同期で待つが、問い合わせは逐次実行する。各CLI呼び出しの制限時間は2分。Describeの標準出力上限は64MiB。検索は`sf api request rest --stream-to-file`で応答を一時ファイルへ直接保存する。検索のAPIバージョンはDescribeの返却パスに合わせ、項目定義との不一致を防ぐ。バージョンを確認できない場合は検索を開始せず停止する。SOQLは同じAPIバージョンのCompositeリクエスト本文に読み取り専用のGETサブリクエストとして格納するため、外側のURLに長いSOQLを含めない。CLI内部で検索結果全件を自動取得・蓄積させない。

### 取得量の調整

固定100項目・200レコードの分割は行わない。生成したSOQL本文が100,000文字を超える場合は、送信前に上限内へ収まる最大の取得範囲を二分探索で計算する。全項目が1レコード分でも収まらない場合は項目を分割し、それ以外はID集合を分割する。WHEREやLIMITも含む実際の文字数を使う。`QUERY_TOO_COMPLICATED`の場合は項目を二分する。

APIが複数ページで結果を返した場合は`nextRecordsUrl`を使って取得する。1回の値取得について全ページの生JSONファイルサイズを合計し、64MiBを超えたらJSON読み込み前に打ち切り、対象レコードを二分して再取得する。1レコードでも超える場合は項目を二分する。各再試行では範囲が必ず縮小し、最小単位でも失敗すれば停止する。認証・権限・タイムアウト・不完全応答は自動分割の対象にしない。

成功した範囲はIDごとのCSV断片として即座に退避する。メモリには全出力ではなく1回の取得結果とその変換分を保持する。最終CSVは64KiBのコピー用バッファで断片を連結する。APIの応答順によらず、対象ID順・指定項目順・全項目の存在を確認してから公開する。通常終了と例外終了では一時ファイルを削除する。

## 出力・更新対象

### レコードフィールドプレビュー（縦型CSV）

1行＝1指定項目。行順は指定ファイルどおり。

| 列               | 内容                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `FieldApiName`   | 項目API名                                                                                                                                                          |
| `Label`          | 項目ラベル                                                                                                                                                         |
| `Type`           | 項目の型                                                                                                                                                           |
| `Value`          | 最新レコードの値、または補完した値                                                                                                                                 |
| `Status`         | `LATEST`: 基準レコードの実値、`SUPPLEMENTED`: 別レコードから補完、`NO_VALUE_FOUND`: 個別検索で実値を取得できず、`NOT_FILTERABLE`: 非NULL条件で検索不可で補完未実施 |
| `SourceRecordId` | 実値の取得元ID。値が見つからない場合は空欄                                                                                                                         |

補完元IDは値の由来を示す固定の付帯列であり、項目行の並び順は変更しない。`Id`・`CreatedDate`の項目行は指定ファイルに記載された場合だけ出力する。

### 横型CSV

ヘッダーは指定項目のAPI名のみ。列順は指定ファイルどおり。1行＝1レコードで、選択時の作成日時降順を維持する。内部照合用の`Id`・`CreatedDate`を自動追加しない。出力したい場合だけ指定ファイルへ記載する。空欄を補完しない。

両形式とも、引用符と改行をCSVの規則でエスケープする。複合値はJSONで保存し、NULLは空セル、Booleanと数値は元の値を保持する。Salesforce側は読み取りのみ。既定の保存先はGit管理対象外で、既存ファイルを上書きしない。

## 権限・実行条件

リポジトリ指定のNode.jsと`sf api request rest --stream-to-file`を利用できるSalesforce CLI、既存認証、API・オブジェクト・項目・レコードへの参照権限が必要。ソート可能なCreatedDate・Idと検索可能なIdを持つオブジェクトに対応する。レコードタイプ指定時は検索可能なRecordTypeIdが必要であり、DescribeのrecordTypeInfosで対象オブジェクトに属するIDか確認する。15桁IDは大小文字を区別して18桁IDの先頭15桁と照合し、18桁IDは完全一致で照合する。レコード作成の可否を表すavailableだけでは読み取りを拒否しない。条件を満たさない場合は理由を表示して停止し、絞り込みを外して続行しない。

## エラー処理

- 終了コード`0`: 完了、対象なし、接続確認成功、または利用者の明示的な中止。
- 終了コード`1`: 入力・接続・検索・ファイル操作の失敗。CSVの完成は保証しない。

ファイル未検出、ディレクトリ指定、アクセス権限などは日本語で対処を案内する。CLI障害は`CLI_NOT_FOUND`、`CLI_ACCESS_DENIED`、`CLI_TIMEOUT`、`AUTH_FAILED`、`BUFFER_LIMIT`、既知のSOQLエラー名、または`CLI_FAILED`へ分類する。判別できない原因を推測せず、生のCLI応答・エラー本文を表示しない。サイズ超過時は、プレビューでは`--fields-per-query`または指定項目数の削減を案内し、横型では`--record-limit`または`--fields-per-query`の削減を案内する。

取得途中は権限を制限した一時ディレクトリへCSV断片を保存し、全取得が成功するまで指定された出力名では公開しない。応答の途中打ち切り、項目欠落、ID重複、対象レコードの消失などを検出した場合も停止する。エラー後に別のレコードへ置き換えたり、取得失敗を空欄として隠したりしない。自動ログイン・再認証は行わない。

## 制約・注意事項

- 個人取引先のレコードタイプが複数あっても指定できるのは1種類。指定なしのプレビューでは法人・個人取引先など異なるタイプの値が混在する場合がある。
- 取得中の更新を同一時点へ固定するトランザクションではない。IDは一致させるが、別クエリの間に更新された値は混在し得る。
- 非NULL条件で検索不可の項目は補完しない。最新レコードで空欄の場合、他のレコードに値があっても空欄のまま出力する。
- サイズ超過・クエリ複雑さは範囲を縮小して再取得するため、制限に当たった場合はAPI呼び出しが増える。1レコード・1項目の失敗は解消できない。
- 一時ファイル用の空き容量が必要。完成ファイルの公開には同一ファイルシステム内のハードリンクを使用するため、対応するローカルファイルシステムが必要。強制終了や電源断では一時ファイルが残る場合がある。
- 特殊なWHERE条件が必須のオブジェクトには対応できない場合がある。
- マスキング・暗号化項目はAPIの応答をそのまま扱う。
- CSVは投入用データを生成する機能ではない。表計算ソフトで開く場合は、数式扱いになる値を文字列として読み込む。
