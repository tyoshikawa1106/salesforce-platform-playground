# 文書検査スクリプト

## 概要

`npm run docs:check`を実行し、リポジトリで管理する現行Markdownの構造、ローカルリンク、安全でないコマンド例、`docs/index.md`からの到達性を検査するNode.jsスクリプトです。

## 目的・利用場面

文書変更時とCIで、リンク切れやMarkdown構造の崩れ、索引への追加漏れ、安全でない操作例を一括確認するために使用します。

## 対象実装・メタデータ

| 種別             | パス                                         | 役割                                               |
| ---------------- | -------------------------------------------- | -------------------------------------------------- |
| npm script       | `docs:check`                                 | 利用者とCIが実行する入口                           |
| Node.js script   | `scripts/docs/check-docs.js`                 | 検査対象を読み込み、問題一覧と終了状態を出力する   |
| Node.js module   | `scripts/docs/internal/markdown-files.js`    | Gitの状態から対象Markdownと除外対象を決定する      |
| Node.js module   | `scripts/docs/internal/validate-docs.js`     | 文書間リンクと索引到達性を検証する                 |
| Node.js module   | `scripts/docs/internal/validate-markdown.js` | Markdown単体の構造、名前、コマンド例を検証する     |
| テストスクリプト | `scripts/docs/test/*.node.js`                | 対象抽出、構造、リンク、安全ルールの分岐を検証する |

## 入力

- 検査内容を変更するコマンドラインオプションは定義していません。追加の引数が指定されても参照しません。
- Git管理済みと、未追跡かつGit除外されていない`.md`ファイルを検査対象候補にします。
- `.agents/skills/`、`docs/knowledge/`、`docs/discussions/`配下は現行文書の検査対象から除外します。
- `.github/pull_request_template.md`はH1を要求しない文書断片として扱います。

## 処理内容

1. Gitから対象Markdownを列挙する。
2. 作業ツリーに存在する対象だけを、`docs/`配下、docs外の単独文書、文書断片へ分類する。
3. `docs/`配下のファイル名が`index.md`またはkebab-caseであることを確認する。
4. 文書断片以外にH1が1件だけあること、見出しレベルが飛ばないこと、コードフェンスが閉じていることを確認する。
5. ローカルリンクのファイルと、Markdownへのリンクで指定されたアンカーが存在することを確認する。
6. `docs/index.md`から文書間リンクを辿り、`docs/`配下の現行文書へ到達できることを確認する。
7. 文書配置ルールで禁止されたPATHやパッケージ導入、一括更新・削除コマンドの例を確認する。
8. 全問題を最後まで収集してまとめて表示する。

## 出力・更新対象

- 文書ファイルは変更しません。
- 問題がなければ、docs、docs外、文書断片の検査件数を標準出力へ表示し、終了コード`0`を返します。
- 問題があれば、総数とファイル、行番号、理由を標準エラー出力へ表示し、終了コード`1`を返します。

## 権限・実行条件

- Node.jsとGitを実行できる必要があります。
- リポジトリのGit管理状態を参照できる作業ツリーで実行します。
- Salesforce組織や外部サービスには接続しません。

## エラー処理

- 構造、リンク、ファイル名、安全ルールの問題は途中で停止せず、検出した内容をまとめて返します。
- 不正なURLエンコードを含むローカルリンクは、リンク元のファイルと行番号を付けて問題として返します。
- 対象列挙またはファイル読み込み自体が失敗した場合は、Node.jsの失敗として非0終了します。

## テスト・確認観点

`npm run test:scripts`に含まれる`scripts/docs/test/*.node.js`で、Git管理対象と未追跡・非除外の列挙条件、削除済み文書の除外、対象分類、H1、見出し、コードフェンス、リンク、URLエンコード、アンカー、索引到達性、安全でないコマンド例を確認します。

文書変更後は次を実行します。

```sh
npm run docs:check
```

## 制約・注意事項

- 文書内容が実装や外部仕様と一致するか、必要な仕様書が網羅されているかは判定しません。
- HTTPまたはHTTPSの外部リンクへアクセスして有効性を確認しません。
- Markdown解析はスクリプトが対応する見出し、コードフェンス、インラインリンク形式を対象とします。
- `docs/knowledge/`と`docs/discussions/`は作成時点の記録であるため、現行文書の検査対象に含めません。

## 既知の差異・確認事項

- 状態: 比較対象なし
- このリポジトリの文書配置ルールを実装した内部検査であり、外部契約との比較対象はありません。
