### ポリシー

#### アプリケーションポリシー

| ラベル               | 役割                                                                                                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 開始ページ           | Salesforce からアプリを起動したときの移動先を選ぶ。OAuth ポリシーの URL を使う場合は［OAuth］、別の移動先を使う場合はカスタムの開始ページを選ぶ。起動画面を設けない API 連携では［なし］。 |
| 選択済みプロファイル | 管理者がアプリの利用を事前承認するプロファイルを選ぶ。管理者だけが使う場合はシステム管理者プロファイルを選ぶ。                                                                             |

#### OAuth ポリシー

##### プラグインポリシー

| ラベル                 | 役割                                                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 許可されているユーザー | 利用者を管理者が指定する場合は［管理者が承認したユーザーは事前承認済み］を選び、対象者にアプリへのアクセスを付与する。利用者自身の判断で認可を許す場合は自己承認を選ぶ。 |
| OAuth 開始 URL         | ［開始ページ］で OAuth を選んだときに利用者を誘導するアプリのページ。認可応答を受け取る URL は［コールバック URL］に設定する。                                           |
| カスタム範囲           | 外部リソースが独自に定義したアクセス範囲を要求する場合に選ぶ。Salesforce の標準 API スコープだけで足りる場合は追加しない。                                               |
| Apex プラグインクラス  | OAuth 処理を Apex で拡張する場合に、実装したクラスを指定する。標準の認証処理を使う場合は空欄。                                                                           |

##### OAuth フローおよび外部クライアントアプリケーションの機能強化

| ラベル                                 | 役割                                                                                                                                    |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| クライアントログイン情報フローを有効化 | ［設定］で有効にしたフローをこの組織で許可する。自動実行用はここもオンにし、直下の［(ユーザー名) として実行］に連携ユーザーを指定する。 |
| (ユーザー名) として実行                | クライアントログイン情報フローで発行されるトークンの実行主体。自動処理に必要なデータ・操作の権限を持つ連携ユーザーを選ぶ。              |

##### アプリケーション認証

| ラベル                                                      | 役割                                                                                                                                                                                             |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 更新トークンポリシー (アイドル状態の有効期間制限を適用済み) | 発行から一定期間で再認可を求める場合は［特定の時間後に更新トークンを期限切れにする］、最後に使用してからの期間で判断する場合は［特定の時間使用されていない更新トークンを期限切れにする］を選ぶ。 |
| 更新トークンの有効期間                                      | 選んだポリシーの期限を数値で指定する。たとえば発行後1日なら「1」、未使用30日なら「30」。どちらも単位は［日］。                                                                                   |
| 更新トークンの有効期間単位                                  | 直前の数値を解釈する単位。接続元に再認可を求めるまでの期間に合わせて選ぶ。                                                                                                                       |
| シングルログアウトを有効化                                  | Salesforce からのログアウトを接続先にも通知する場合にオンにし、接続先が受け付けるログアウト URL を設定する。                                                                                     |
| 高保証セッションが必要です                                  | 高保証レベルのセッションでの利用を要求する場合にオンにする。通常のセッションで利用を許可する場合はオフ。                                                                                         |
| カスタム属性                                                | 接続先が認証時に受け取る独自の属性を要求する場合に、その名前と値を定義する。                                                                                                                     |

| 取引先責任者 電話                  | アプリの管理連絡先として電話での問い合わせも受ける場合に登録する。                                                                                    |

| アイコン URL                       | アプリを識別するアイコンを指定する場合に、アイコン画像の URL を登録する。                                                                             |
| ロゴ画像 URL                       | アプリ固有のロゴを表示する場合に、ロゴ画像の URL を登録する。                                                                                         |
| 説明                               | 管理者が用途を判別できるよう、接続元・対象機能・誰の権限で実行するかを記載する。                                                                      |

#### OAuth 設定

##### アプリケーション設定

| ラベル                 | 役割                                                                                                                                                                                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| コールバック URL       | ブラウザーでの本人認証では、接続元が認可応答を受け取る URL を登録し、認可要求の redirect_uri と一致させる。組織内の外部認証 ID プロバイダーを使う場合は、そのプロバイダーのコールバック URL を使う。クライアントログイン情報フローの実行時には使用しない。 |
| 選択した OAuth 範囲    | Salesforce API の利用には api、本人の再ログインなしでトークンを更新するには refresh_token（offline_access）、OpenID Connect で本人を識別するには openid を選ぶ。自動実行で API を呼ぶだけなら api を選ぶ。                                                 |
| すべてのトークンを調査 | 他のアプリに発行されたトークンもイントロスペクションで調査する必要がある場合にオンにする。自分のアプリのトークンだけを調査する場合はオフ。                                                                                                                 |
| ID トークンを設定      | OpenID Connect の ID トークンの内容などを個別に設定する場合にオンにする。openid スコープの付与は［選択した OAuth 範囲］で行う。                                                                                                                            |

##### フローの有効化

| ラベル                                     | 役割                                                                                                                                         |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| クライアントログイン情報フローを有効化     | 利用者のログイン操作なしにサーバー間で API を呼ぶアプリでオンにする。本人の認可コードで接続するアプリはオフ。                                |
| 認証コードおよびログイン情報フローを有効化 | 接続元が Salesforce のヘッドレス認証を実装する場合にオンにする。利用者を Salesforce のログイン画面に誘導する通常の認可コードフローではオフ。 |
| デバイスフローを有効化                     | 入力が難しい端末から接続し、利用者が別端末のブラウザーで認可する構成でオンにする。                                                           |
| JWT ベアラーフローを有効化                 | 接続元が秘密鍵で署名した JWT を使って認証する場合にオンにし、署名の検証に使う証明書を登録する。                                              |
| トークン交換フローを有効化                 | 外部の ID プロバイダーが発行したトークンを Salesforce のアクセストークンに交換する場合にオンにする。                                         |

##### セキュリティ

| ラベル                                                                   | 役割                                                                                                                                                           | クライアントログイン情報フローへの影響                                                                                  |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Web サーバーフローの秘密が必要                                           | 認可コードの交換時に接続元のクライアントシークレットを要求する。秘密を安全に保持して送信できるサーバー側の接続でオンにする。                                   | 影響なし。オフでも、クライアントログイン情報フローのトークン取得にはクライアント ID と秘密が必要。                      |
| 更新トークンフローの秘密が必要                                           | 更新トークンからアクセストークンを再取得する際にクライアントシークレットを要求する。オンにする場合は接続元が更新要求にも秘密を付けて送信できることを確認する。 | 影響なし。更新トークンは発行されず、更新要求も行わない。                                                                |
| サポートされる認証フローに Proof Key for Code Exchange (PKCE) 拡張を要求 | 認可コードを取得した接続元を交換時に検証する。本人認証の接続元は認可時に code_challenge、交換時に対応する code_verifier を送る。この組織ではオンが必須。       | 影響なし。認可コードを交換する工程がなく、PKCE の検証値は使用しない。                                                   |
| 更新トークンのローテーションを有効化                                     | 更新時に新しい更新トークンを発行する。接続元は更新のたびに新しいトークンを保存し、次回からそれを使う。この組織ではオンが必須。                                 | 影響なし。アクセストークンが失効したら、アプリの資格情報で新しいアクセストークンを取得する。                            |
| 指名ユーザーの JSON Web トークン (JWT) ベースのアクセストークンを発行    | 指名ユーザー向けに JWT 形式のアクセストークンを発行する場合にオンにする。通常の不透明なアクセストークンを使う構成はオフ。                                      | 影響あり。オンにすると、指定した実行ユーザーのアクセストークンが JWT 形式で発行される。                                 |
| アイドル状態更新トークンの有効期間 (TTL) を 30 日に制限                  | 未使用の更新トークンに30日の上限を適用する。この組織ではオンが必須。アプリごとの失効条件は［更新トークンポリシー］で選ぶ。                                     | 影響なし。30日は更新トークンの未使用期間の上限で、このフローのアクセストークンの寿命には適用されない。                  |
| Demonstrating Proof of Possession (DPoP) 拡張を必須にする                | トークンを接続元の鍵に結び付ける場合にオンにする。接続元がその鍵で DPoP 証明を生成して送信できることが前提。                                                   | 影響あり。オンにすると、サーバーはトークン取得時と対応 API の呼び出し時に、同じ鍵で署名した DPoP 証明を送る必要がある。 |

## 本人認証用と自動連携用のアプリの分け方

### 接続と実行ユーザー

| 比較項目                                   | 本人認証用                                                                           | 自動連携用                                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| アプリを分ける目的                         | 利用者のログインを受け付け、本人の権限でのアクセスを管理する。                       | サーバーの資格情報と連携ユーザーの権限を管理する。自動連携だけを停止・更新できる。              |
| 接続元が使う資格情報                       | 本人認証用アプリのクライアント ID で認可を開始し、利用者がブラウザーでログインする。 | サーバーが自動連携用アプリのクライアント ID と秘密で認証する。                                  |
| API の実行ユーザー                         | ログインして認可した利用者本人。                                                     | ［(ユーザー名) として実行］に指定した連携ユーザー。トークンから処理を起動した人は識別できない。 |
| ［クライアントログイン情報フローを有効化］ | オフ。ブラウザーでの認可には認可コードフローを使う。                                 | ［設定］と［ポリシー］の両方でオン。この設定だけでブラウザーからの認可が禁止されることはない。  |
| コールバック URL                           | 接続元が認可応答を受け取る URL。認可要求の `redirect_uri` と一致させる。             | クライアントログイン情報フローでは使用しない。                                                  |

### OAuth 範囲とトークンの更新

| 比較項目                                               | 本人認証用                                                                                         | 自動連携用                                                                                                                         |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| ［選択した OAuth 範囲］                                | API 利用には `api`、OpenID Connect で本人を識別する場合は `openid` を選択する。                    | API 連携には `api` を選択する。                                                                                                    |
| ［いつでも要求を実行 (refresh_token, offline_access)］ | 再ログインせずに接続を継続したい場合に選択し、更新トークンの発行を許可する。                       | 選択しない。クライアントログイン情報フローは更新トークンを発行しない。このスコープの有無は、ブラウザーからの認可の可否を決めない。 |
| ［更新トークンフローの秘密が必要］                     | オンの場合、発行済みの更新トークンを使う際にクライアントシークレットを送る。                       | クライアントログイン情報フローには適用されない。                                                                                   |
| ［更新トークンポリシー］                               | 発行済みの更新トークンがいつ失効するかを定める。                                                   | クライアントログイン情報フローには適用されない。                                                                                   |
| アクセストークンの期限が切れたとき                     | 有効な更新トークンで再取得する。更新トークンがない場合や失効した場合は、再び利用者の認可を受ける。 | サーバーが同じアプリの資格情報で新しいアクセストークンを取得する。                                                                 |

## OAuth の認可 URL と curl の実行例

例の `https://sf.example.com` は組織の My Domain URL に、`https://app.example.com/oauth/callback` は本人認証用アプリの登録済みコールバック URL に置き換える。認可 URL の `{…}` には URL エンコードした値を入れる。curl の `$` で始まる変数にはエンコード前の値を設定する。

### 本人認証用：認可コードを受け取る

**リクエスト**　利用者のブラウザーを認可エンドポイントへ誘導する。接続元は認可要求ごとにランダムな `state` と `code_verifier` を生成し、利用者のセッションに保持する。`code_challenge` には `code_verifier` の SHA-256 ハッシュを Base64URL エンコードした値（パディングなし）を送る。

```text
https://sf.example.com/services/oauth2/authorize?response_type=code&client_id={per_user_client_id}&redirect_uri=https%3A%2F%2Fapp.example.com%2Foauth%2Fcallback&scope=api%20refresh_token&state={state}&code_challenge={code_challenge}&code_challenge_method=S256
```

**レスポンス**　利用者のログイン・認可が完了すると、Salesforce は登録済みのコールバック URL にブラウザーを戻す。接続元は返された `state` がセッションの値と一致することを確認し、`code` を次の交換に一度だけ使う。

```text
https://app.example.com/oauth/callback?code={authorization_code}&state={state}
```

### 本人認証用：認可コードを交換してリフレッシュトークンを受け取る

**リクエスト**　接続元のサーバーが、受け取った認可コードと認可開始時の `code_verifier` を送る。`redirect_uri` は認可要求と同じ値を使う。

```sh
curl 'https://sf.example.com/services/oauth2/token' \
  --data-urlencode 'grant_type=authorization_code' \
  --data-urlencode "client_id=$PER_USER_CLIENT_ID" \
  --data-urlencode "client_secret=$PER_USER_CLIENT_SECRET" \
  --data-urlencode "code=$AUTHORIZATION_CODE" \
  --data-urlencode 'redirect_uri=https://app.example.com/oauth/callback' \
  --data-urlencode "code_verifier=$CODE_VERIFIER"
```

**レスポンス**　この例では本人認証用アプリで `refresh_token` スコープを許可し、認可時にも要求している。`access_token` は API 呼び出しに使い、`refresh_token` は次回の更新用にサーバー側で利用者の接続ごとに保存する。

```json
{
    "access_token": "{user_access_token}",
    "refresh_token": "{user_refresh_token}",
    "token_type": "Bearer"
}
```

### 本人認証用：リフレッシュトークンでアクセストークンを更新する

**リクエスト**　接続元のサーバーが、同じアプリの資格情報と保存済みの最新のリフレッシュトークンを送る。

```sh
curl 'https://sf.example.com/services/oauth2/token' \
  --data-urlencode 'grant_type=refresh_token' \
  --data-urlencode "client_id=$PER_USER_CLIENT_ID" \
  --data-urlencode "client_secret=$PER_USER_CLIENT_SECRET" \
  --data-urlencode "refresh_token=$USER_REFRESH_TOKEN"
```

**レスポンス**　更新トークンのローテーションがオンの場合、新しい `refresh_token` も返る。同じ接続の更新要求は直列に実行し、次の要求には保存し直した新しい値を使う。

```json
{
    "access_token": "{new_user_access_token}",
    "refresh_token": "{new_user_refresh_token}",
    "token_type": "Bearer"
}
```

### 自動連携用：アプリの資格情報でアクセストークンを取得する

**リクエスト**　自動連携用のサーバーからトークンエンドポイントへ直接送る。`grant_type=client_credentials` ではブラウザーでの認可を行わず、認可コードも PKCE の検証値も使用しない。

```sh
curl 'https://sf.example.com/services/oauth2/token' \
  --data-urlencode 'grant_type=client_credentials' \
  --data-urlencode "client_id=$INTEGRATION_CLIENT_ID" \
  --data-urlencode "client_secret=$INTEGRATION_CLIENT_SECRET"
```

**レスポンス**　［(ユーザー名) として実行］で指定した連携ユーザーのアクセストークンが返る。リフレッシュトークンは発行されない。期限が切れたら同じリクエストで新しいアクセストークンを取得する。

```json
{
    "access_token": "{integration_access_token}",
    "token_type": "Bearer"
}
```
