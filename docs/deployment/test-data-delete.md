# テストデータ一括削除手順

開発組織のテストデータを、[一括削除画面](../specifications/lwc/test-data-delete/index.md)から削除します。インポートしたレコードだけでなく、対象オブジェクト内の全レコードを削除します。

## 事前確認

- 対象組織と画面のオブジェクト一覧を確認する。
- 「すべてのデータの編集」の実効権限を確認する。ファイルは実行ユーザーが照会できる範囲を対象とする。
- 必要なデータを組織のバックアップ手段で退避し、処理中のデータ投入・編集を停止する。
- 「Salesforce」アプリの「テストデータ一括削除」タブを開く。`TestDataDelete`タブとアプリのナビゲーション設定を機能と一緒に反映する。

## 実行

1. 画面で対象組織・削除順序・残件数を確認する。
2. 「全件削除」を選び、確認ダイアログで承認する。
3. 受付ジョブIDを確認する。画面を閉じても処理は継続する。
4. 「実行状況・残件数を確認」で再確認する。受付ジョブ一件の終了を全体完了と扱わない。
5. 実行中ジョブがなく、全対象の残件数がゼロであることを確認する。

## 停止・失敗時

結果メールで停止理由を確認し、設定のApexジョブで`TestDataDeleteBatch`の失敗・中断も確認します。メールで通知した途中停止では標準ジョブがCompletedになるため、ジョブ状態だけで全体成功と判断しません。権限、参照制約、レコードの状態、Trigger・Flowなどの原因を解消してから画面で残件数を確認し、必要なら再実行します。

受付応答が失われたときは再送せず、Apexジョブを確認してから画面を開き直します。成功済みの削除は自動で元に戻りません。通常削除の復元可否はオブジェクトと標準の連動削除に依存するため、ごみ箱だけをバックアップの代わりにしません。

対象・権限・順序・停止条件の詳細は[バッチ仕様](../specifications/apex/batches/test-data-delete/index.md)を参照してください。匿名Apex・CLI・定期起動による削除の手順は提供しません。

## Scratchでの結合検証

Apex単体テストでは複数の非同期スコープとバッチチェーン全体は実行できません。単一スコープ、状態の直列化を挟む複数スコープの直接呼び出し、後続ジョブ登録をそれぞれ検証し、以下を新規の検証用Scratchで別途確認します。

1. 組織種別・有効期限を確認し、専用Scratchへ機能・タブ・依存メタデータを限定反映する。
2. 実行者の「すべてのデータの編集」とタブ・Apexクラスへのアクセスを確認する。
3. [テストデータ投入手順](test-data-import.md)の投入planで合成データを投入する。AccountとContactは、起動箇所のバッチサイズを超え、複数スコープが必要になる件数を用意する。
4. Chromeで専用タブを開き、対象・順序・投入後の残件数を確認する。
5. 画面の「全件削除」から開始する。匿名Apex・CLIで削除を開始しない。
6. 固定計画の全段階の標準Apexジョブが終了し、`NumberOfErrors=0`、Account・Contactの`TotalJobItems`と`JobItemsProcessed`が複数スコープ分で一致することを確認する。各ジョブの前段完了後に次段が作成されることも確認する。
7. 画面を更新し、全対象の残件数ゼロを確認する。ジョブと件数の照会結果を検証証跡として保管する。

dev組織の既存レコードを結合検証のために削除しません。Scratchの作成、権限設定、投入、画面からの全件削除は対象と範囲を明示して実施します。検証用Scratchの削除は別途明示された場合だけ行います。
